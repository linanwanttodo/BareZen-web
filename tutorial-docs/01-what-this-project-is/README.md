# 第 1 章：它是什么，值在哪

## 本章目标

第一章不写安装步骤，也不比较框架优劣。它先给 BareZen 一个准确位置：这是理解 HTTP 框架内部原理的学习项目，同时是能运行小型同步服务的轻量骨架。然后用手写路由、安全边界、测试策略和版本模型四个例子说明，哪些代码值得亲手写，哪些“方便”会让设计失去可解释性。

读者完成后应能区分功能数量与设计质量，知道本项目追求的是把规则写清、用测试守住，而不是宣称自己已经覆盖成熟框架的全部场景。第一章也没有制造一个新框架；它是在解释后续十二章为何按这个顺序展开。

## 涉及 ADR

- [ADR-0002：JDK 17 字节码基线与运行期能力](../../docs/adr/0002-jdk-17-baseline-with-runtime-capability-instead-of-jdk-modules.md)：父 POM 统一声明 release 17，产物可以在 JDK 17 及以上加载。需要 Java 21 的行为通过运行期能力探测选择，不按 JDK 版本分裂模块。代价是保留一小段显式探测代码，并在每次升级时重新审视它。
- [ADR-0019：路由语义](../../docs/adr/0019-router-semantics.md)：Router 只回答 method 与原始 path 对应哪个 Handler，以及捕获了什么。它不解码、不归一化、不调用 Handler，也不生成错误响应。精确规则让歧义在注册或匹配时暴露，而不是留给部署环境猜测。
- [ADR-0033：安全是 Handler 装饰器](../../docs/adr/0033-security-is-a-handler-decorator.md)：认证、授权和业务处理被包成一个 Handler，而不是散进服务器适配器。固定顺序保证被拒绝的请求不会进入业务代码，也让安全可以在没有 socket 的测试中独立验证。
- [ADR-0034：认证三态](../../docs/adr/0034-authentication-has-three-states.md)：没有凭据、凭据错误和认证成功是三种不同事实，不能压成布尔值。三态让 401 与 403 的边界可表达，同时要求新增状态时重新检查所有消费者。
- [ADR-0036：不透明且可撤销的会话](../../docs/adr/0036-sessions-are-opaque-and-revocable.md)：会话 token 是不可猜测的随机值，状态由 SessionStore 保存并可失效。它不把身份直接编码进 token，因此撤销不需要等待签名过期，但当前内存实现也不提供重启恢复或多实例共享。
- [ADR-0037：状态码与默认拒绝](../../docs/adr/0037-status-codes-and-default-deny.md)：无身份或认证失败返回 401，已知身份但授权不足返回 403，安全组件自身异常返回 500。默认拒绝和固定响应体避免把认证器提供的诊断细节泄露给客户端。
- [ADR-0044：TestKit 是向下依赖的测试工具](../../docs/adr/0044-testkit-is-a-downward-only-test-tool.md)：集成测试启动真实 JDK 适配器和随机端口，不拿内存分派冒充网络。TestKit 只依赖下层模块，且不能反向进入框架或插件生产依赖。
- [ADR-0045：示例是只使用公开 API 的叶子](../../docs/adr/0045-examples-are-a-leaf-public-api-only.md)：示例只编译生产公开 API，使用真实 socket 和真实驱动。它们既是可运行说明，也是防止内部实现被误当成稳定接口的消费者。
- [ADR-0008：没有模块内容就不建聚合模块](../../docs/adr/0008-no-aggregator-pom-without-modules.md)：空目录和只有 POM 占位符的模块会制造虚假的结构感。模块只有在自己拥有职责和产物时才进入 reactor，这能让依赖图直接说明真实边界。

## 本章完成后的能力清单

读完本章，你应能用一句话说明 BareZen 的定位，能指出它当前不是生产级通用框架，也不会因为“不依赖 Spring”就推导出性能或生态优劣。你能说出为什么 Router 不直接返回 404，为什么认证失败与授权拒绝不能共用一个 Optional，以及为什么真实端口测试不能由直接调用 Handler 替代。

你还会建立一个版本判断习惯：先查编译 release，再查字节码 major，最后查运行期能力选择。开发机是 JDK 24 并不等于项目要求所有消费者使用 JDK 24；字节码基线 17 与 JDK 21+ 虚拟线程可以同时成立。

## 不这样设计会坏掉什么

如果把路由图方便而加入解码、重定向和异常处理，一个组件就要同时拥有 URL 政策、响应格式和资源映射。后续插件无法判断自己注册的路径会在哪一层被改写，安全审计也不能只检查路由表。

如果把认证压成“有 principal 就算成功”，匿名请求和错误 token 会失去区别，401 与 403 的选择只能靠调用方猜测。如果把会话做成不可撤销的签名身份，登出就只能删除客户端副本，服务端无法主动终止它。

如果测试只调用 Handler，HEAD 分帧、Content-Length、请求体读取和 socket 关闭都从未发生；如果只有示例没有架构门禁，新增一条反向依赖也不会被任何业务测试发现。门禁不是为了增加仪式感，而是把设计者不愿重复解释的边界交给构建流程。
