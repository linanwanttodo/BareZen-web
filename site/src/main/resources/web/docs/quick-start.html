Quick start

One handler, one route table, one server. Everything else is a module you add on purpose.

Coordinates

Import the BOM once, then depend on what you use. Nothing in the framework depends on barezen-security, barezen-data, barezen-content, barezen-plugins, barezen-http-servlet or barezen-testkit — the direction is one way, which is what lets a second application run a different set.

<dependencyManagement><dependencies>
  <dependency>
    <groupId>com.barezen</groupId><artifactId>barezen-bom</artifactId>
    <version>0.1.0-SNAPSHOT</version><type>pom</type><scope>import</scope>
  </dependency>
</dependencies></dependencyManagement>

<dependencies>
  <dependency><groupId>com.barezen</groupId><artifactId>barezen-web</artifactId></dependency>
  <dependency><groupId>com.barezen</groupId><artifactId>barezen-http-jdk</artifactId></dependency>
</dependencies>

The repository publishes nothing yet — no remote, no artifact, no license file — so a sibling project consumes it today with mvn install. The absence is recorded in ADR-0046 rather than filled in with a plausible URL.

The first route

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", (request, params) ->
        new Response(200, Headers.of("Content-Type", "text/plain"), OK))
    .route(HttpMethod.GET, "/users/{id}", (request, params) ->
        new Response(200, Headers.of("Content-Type", "application/json"),
            ("{\"id\":\"" + params.get("id") + "\"}").getBytes(StandardCharsets.UTF_8)))
    .build();

JdkHttpServerAdapter server = new JdkHttpServerAdapter(new InetSocketAddress("127.0.0.1", 0), router);
server.start();
int port = server.port().getAsInt();
server.stop();

Port 0 asks the operating system; name the port your deployment owns. start() may be called once per instance and stop() is idempotent and never throws — one instance is one server lifecycle, and restarting the same object would mean the caller's reference names a server that no longer exists (ADR-0024, ADR-0012, ADR-0005).

What a handler can ask for

A handler is Response handle(Request request, Map<String,String> parameters). That is the whole extension surface of the web layer, and it is short on purpose:

  • the request carries what the client sent — method, raw path, raw query (absent is distinct from empty), header fields one per value, and body bytes;
  • captured path parameters arrive as the second argument, not as request state and not through a thread-local;
  • the response carries a status, fields and a byte[] body, and it refuses Content-Length and Transfer-Encoding because framing belongs to the server (ADR-0020, ADR-0027).

A handler that needs to know who is asking implements SecuredHandler beside Handler and is given a third argument by the security decorator. A bare three-argument lambda is not a Handler, so it cannot be wrapped — that shape is refused by the detection rule rather than by convention.

Run the examples

The examples/ module holds seven programs — hello world, routing, request/response, security, database, plugin, OpenAPI — each with a main() that binds a real socket and prints what it observed, and each with a test the reactor runs. Build first, then one java -cp per program:

mvn -o -B -ntp clean verify
java -cp "$CP" com.barezen.examples.hello.HelloWorld

The classpath recipe and the observed output of all seven are in docs/examples/README.md.
