Two servers, one table

Identical by assertion in both: the six answers and their bodies, Allow ordering, framing (a length for a body, none for 204/304), HEAD stating a length it does not send, the lowercase-token asymmetry, the 1 MiB default bound, and a handler exception reaching the log rather than the socket.

Three things a servlet container decides before BareZen can answer, measured and recorded rather than smoothed over: a percent-encoded slash in a path, a body shorter than its declared Content-Length, and TRACE each come back as the container's own HTML error page — one of them carrying an exception report — and the container rewrites whitespace in a Content-Type parameter. Replacing those pages is deployment policy, named as open work (ADR-0049 §7).

The decisions, by number

Fifty-five ADRs sit in docs/adr/, each one decision, each with the alternatives it refused, the tests that prove it, a non-goal list and a reopening trigger. Still open, by name

  • Route enumeration. A route is declared once as a route and once as OpenAPI metadata, because the table exposes no inspection answer. The fix needs ADR-0019 §19 amended with a test that proves the merge step is not what arrives instead (ADR-0047, ADR-0042).
  • Injection into discovered plugins. A discovered plugin needs nothing; the answer to needing something is an explicit factory, not a lookup (ADR-0048).
  • A second extension point. The event bus has had no consumer since 2.6 and is the named candidate (ADR-0047).
  • Streaming bodies, range requests, conditional Last-Modified, cache policy, error-page representation, mTLS, an embedded container adapter, a license file, a published artifact. Each is a deferral with a trigger in the record named beside it; none is a TODO.
  • Translation alignment. The Chinese pages are a hand-maintained mirror of these ones, file for file. The build proves a counterpart exists and that the two links resolve in both directions; it cannot prove a Chinese paragraph still says what the English one says. That drift is bounded by "both files in one commit", not by a machine (ADR-0053).

Preview and deploy this documentation

./scripts/check-site.sh                    # every link resolves on disk, both languages pair up
python3 -m http.server 8000                # preview at http://127.0.0.1:8000/site/

The tree is a folder of files with relative addresses, so it deploys unchanged to any static host: on GitHub Pages that is Settings → Pages → Deploy from a branch, main, the /site folder. The reason nothing here needs a server of ours is the reason the links are relative: a project page lives under /repo/site/, where an address starting /assets/… resolves above the site and 404s. What the static host does not give you is named too: no conditional GET, no generated /openapi.json, and a URL keeps the .html its file has (ADR-0054).

Build and verify

mvn -o -B -ntp clean verify          # unit, integration, architecture, coverage gate
./scripts/check-jdk-baseline.sh      # the declared release is still 17
./scripts/check-class-major.sh       # every emitted class file is major 61
./scripts/check-site.sh              # the documentation tree is self-consistent

JDK 17 is the compatibility baseline and JDK 21 or later is the recommended runtime; virtual threads are a runtime capability probed at startup, never a build variant (ADR-0002, ADR-0010).
