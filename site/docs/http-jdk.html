JDK HTTP adapter

barezen-http-jdk provides an HttpServerAdapter on the JDK's built-in com.sun.net.httpserver, with virtual thread support and TLS/HTTPS.

Module overview

The barezen-http-jdk module adapts the JDK's own HTTP server (com.sun.net.httpserver) to the BareZen web contract. This is the only module in the framework that names that package — everything else stays server-agnostic (ADR-0021).

Key features:

  • Virtual threads on Java 21+. Auto-detects and uses virtual threads when available, platform threads otherwise.
  • TLS/HTTPS support. Configurable via keystore path and password.
  • Request body limit. Prevents denial-of-service from unbounded body reads.
  • Error handling. Produces 404, 405, 400, 413, and 500 responses for routing and protocol errors.

Constructors

There are three public constructors, each with different configuration options:

Simple constructor (auto-configured)

InetSocketAddress address = new InetSocketAddress("0.0.0.0", 8080);
JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(address, router);

This constructor:

  • Creates its own ThreadProvider with ThreadPolicy.AUTO (virtual threads on Java 21+, platform threads otherwise).
  • Uses the default request body limit from the configuration key's default value.
  • Serves plaintext HTTP (no TLS).
  • Owns the thread provider and closes it on stop().

Constructor with shared ThreadProvider

ThreadProvider threads = ThreadProviders.create(
    ThreadPolicy.VIRTUAL, RuntimeCapabilities.detect());

JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, threads);

This constructor borrows the thread provider — it creates one executor from it but never closes either. The caller owns the provider and should close it after adapter.stop().

Constructor with Configuration

Configuration config = Configuration.standard(
    Path.of("application.properties"));

JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, config);

This constructor reads the following configuration keys:

KeyTypeDefaultDescription
barezen.http.jdk.maxRequestBodyBytesLong1 MBMaximum request body size in bytes. Requests exceeding this limit are rejected with 413.
barezen.http.jdk.tls.keystorePathStringNone (plaintext)Path to the keystore file (JKS or PKCS12). Absent means plaintext HTTP.
barezen.http.jdk.tls.keystorePasswordStringRequired if keystorePath is setPassword to open the keystore. Required when keystorePath is present.

Lifecycle

The adapter follows a strict lifecycle: NEW → RUNNING → STOPPED, with no path back. A second start() throws, as does start → stop → start. A restart requires building a new adapter.

Start

adapter.start();
// Server is now listening on the configured address
int port = adapter.port().getAsInt();  // The actual bound port

start() binds the port and begins accepting connections. If binding fails (e.g., port already in use), it throws UncheckedIOException and leaves the adapter in the STOPPED state.

Stop

adapter.stop();  // Idempotent, never throws

stop() gives in-flight exchanges 3 seconds to complete, then releases resources. It is idempotent — calling it on a never-started adapter is legal and does nothing.

Query methods

boolean running = adapter.isRunning();  // true between start() and stop()
OptionalInt port = adapter.port();      // The actual bound port (empty if not running)

TLS / HTTPS configuration

To enable HTTPS, configure the keystore path and password in your application.properties:

# application.properties
barezen.http.jdk.tls.keystorePath=/path/to/keystore.p12
barezen.http.jdk.tls.keystorePassword=changeit

Or set them via environment variables:

export BAREZEN_HTTP_JDK_TLS_KEYSTOREPATH=/path/to/keystore.p12
export BAREZEN_HTTP_JDK_TLS_KEYSTOREPASSWORD=changeit

Creating a keystore

Use the JDK's keytool to create a keystore:

# Create a PKCS12 keystore with a self-signed certificate
keytool -genkeypair \
  -alias server \
  -keyalg RSA \
  -keysize 2048 \
  -storetype PKCS12 \
  -keystore keystore.p12 \
  -validity 365 \
  -dname "CN=localhost, OU=Dev, O=MyOrg, L=City, ST=State, C=US" \
  -storepass changeit \
  -keypass changeit

TLS protocol

The adapter uses TLSv1.2 as the ceiling with TLSv1.3 preferred, which is the JDK's default ordering. No protocol list is configured, no cipher suite is chosen, and no client certificate is requested (no mTLS).

Error handling

  • If keystorePath is set but keystorePassword is absent, construction fails with ConfigurationException.
  • If the keystore file cannot be opened, construction fails with ConfigurationException naming the path and the JDK exception.
  • The password is never echoed in error messages or logs.

Request body limit

The adapter enforces a maximum request body size to prevent denial-of-service attacks. The default is 1 MB (1,048,576 bytes). Requests exceeding this limit are rejected with 413 Payload Too Large before the handler runs.

Configure the limit in application.properties:

# application.properties
barezen.http.jdk.maxRequestBodyBytes=5242880  # 5 MB

Thread model

By default, the adapter creates its own ThreadProvider with ThreadPolicy.AUTO:

  • Java 21+ — Each request runs on a virtual thread. This provides high concurrency with low memory overhead.
  • Java 17 — Each request runs on a platform thread from a cached pool.

To force a specific thread model, use the constructor with a shared ThreadProvider:

ThreadProvider threads = ThreadProviders.create(
    ThreadPolicy.VIRTUAL, RuntimeCapabilities.detect());

JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, threads);

Error responses

The adapter handles the following error cases:

StatusWhen
400 Bad RequestMalformed request line or invalid HTTP method.
404 Not FoundNo route matches the request method and path.
405 Method Not AllowedA route exists for the path but not for the requested method. The Allow header lists the allowed methods.
413 Payload Too LargeRequest body exceeds the configured limit.
500 Internal Server ErrorHandler threw an exception. The error body contains no details — only the server log does.

Usage with LifecycleOrchestrator

Configuration config = Configuration.standard(
    Path.of("application.properties"));

InetSocketAddress address = new InetSocketAddress("0.0.0.0", 8080);
JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, config);

LifecycleOrchestrator orchestrator = LifecycleOrchestrator.builder()
    .register("http", adapter)
    .build();

try {
    orchestrator.start();
    // Server is running
} finally {
    orchestrator.stop();
}

Usage with ephemeral port

For tests or when you want the OS to pick a free port, use port 0:

InetSocketAddress address = new InetSocketAddress("127.0.0.1", 0);
JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(address, router);
adapter.start();

int actualPort = adapter.port().getAsInt();
System.out.println("Server listening on port " + actualPort);

Best practices

  • Use the Configuration constructor in production to read body limits and TLS settings from config files.
  • Use port 0 in tests to avoid port conflicts between parallel test runs.
  • Register the adapter as the last participant in the orchestrator, so routes are fully set up before the server binds.
  • For HTTPS, use a PKCS12 keystore (the JDK default since Java 9).
  • Never expose the keystore password in logs or error messages — the framework enforces this.

Common issues

"Address already in use"

The port is already bound by another process. Either change the port or stop the other process. Use lsof -i :8080 or netstat -tlnp | grep 8080 to find the process.

"keystorePath names a keystore but keystorePassword supplies no password"

You set the keystore path but forgot the password. Both keys are required for TLS. Set barezen.http.jdk.tls.keystorePassword in your configuration.

"cannot start the JDK HTTP server on ..."

The bind failed. Check that the host address is correct (use 0.0.0.0 for all interfaces, 127.0.0.1 for localhost only) and that the port is available.

"this adapter is STOPPED and cannot be started again"

The adapter was already stopped. Build a new JdkHttpServerAdapter instance to restart. The adapter does not support restart — one instance, one lifecycle.
