Servlet integration

barezen-http-servlet provides BarezenServlet, a standard HttpServlet that dispatches to a BareZen Router inside Tomcat, Jetty, or Wildfly.

Module overview

The barezen-http-servlet module integrates BareZen with the Jakarta Servlet API. Instead of running your own HTTP server, you deploy a standard WAR file to an existing servlet container. The container owns the port, thread pool, executor, and lifecycle — BareZen only provides the routing and handler dispatch.

BarezenServlet is not an HttpServerAdapter. An adapter starts, stops, reports its bound port, and cannot restart. A servlet instantiated by a container it does not control cannot honestly answer port() or isRunning() (ADR-0049).

Two deployment modes

There are two ways to hand over the route table, because a container instantiates what it deploys:

1. Programmatic embedding

The application builds the router and hands it to the servlet constructor:

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", (req, params) ->
        new Response(200, Headers.of("Content-Type", "text/plain"), "OK".getBytes()))
    .build();

BarezenServlet servlet = new BarezenServlet(router);
// Register the servlet with the container programmatically

2. Declarative deployment (web.xml or @WebServlet)

The container instantiates the servlet via its no-argument constructor. The application's ServletContextListener sets the router as a context attribute at startup:

// In your ServletContextListener:
public void contextInitialized(ServletContextEvent event) {
    Router router = Router.builder()
        .route(HttpMethod.GET, "/health", healthHandler)
        .build();
    event.getServletContext().setAttribute(
        BarezenServlet.ROUTER_ATTRIBUTE, router);
}

web.xml configuration

<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         version="6.0">

  <servlet>
    <servlet-name>barezen</servlet-name>
    <servlet-class>com.barezen.http.servlet.BarezenServlet</servlet-class>
    <init-param>
      <param-name>barezen.maxRequestBodyBytes</param-name>
      <param-value>5242880</param-value>
    </init-param>
    <load-on-startup>1</load-on-startup>
  </servlet>

  <servlet-mapping>
    <servlet-name>barezen</servlet-name>
    <url-pattern>/</url-pattern>
  </servlet-mapping>

</web-app>

@WebServlet annotation

@WebServlet(
    urlPatterns = "/*",
    initParams = @WebInitParam(
        name = "barezen.maxRequestBodyBytes",
        value = "5242880"))
public class MyServlet extends BarezenServlet {
}

Configuration

The servlet reads its configuration once during init():

Init parameterTypeDefaultDescription
barezen.maxRequestBodyByteslong1 MB (1,048,576 bytes)Maximum request body size. Requests exceeding this limit are rejected with 413.

If the parameter is present but not a valid number — an empty or whitespace-only value included — the deployment fails with a ServletException naming the parameter and the value found. Only an absent parameter falls back to the default.

ServletContext attribute

For declarative deployment, the router must be placed under the attribute name com.barezen.http.servlet.router (accessible as BarezenServlet.ROUTER_ATTRIBUTE) before the servlet initializes.

Error responses

Identical to the JDK adapter — switching server must not change what a client reads (ADR-0023):

StatusWhen
400 Bad RequestMalformed request target or body never arrived.
404 Not FoundNo route matches the request method and path.
405 Method Not AllowedA route exists for the path but not for the requested method. The Allow header lists the allowed methods.
413 Payload Too LargeRequest body exceeds the configured limit.
500 Internal Server ErrorHandler threw an exception. The stack trace goes to the log, not to the client.

Thread safety

One servlet instance serves every request concurrently. It holds nothing but the route table and one number (the body limit), so there is no per-request state to leak. The servlet specification guarantees init() happens-before the first service() call, making those two fields safe to read without a lock.

What the servlet does not do

  • It does not parse HTTP — the container refuses a malformed request line before a request object exists.
  • It does not answer OPTIONS * — the container resolved a target before routing.
  • It does not log one line per request — access logging is the container's job.
  • It does not catch Error — an OutOfMemoryError inside a handler is not a condition a 500 answers.

Supported containers

The servlet module depends on the Jakarta Servlet API (jakarta.servlet). It has been tested with:

  • Apache Tomcat 10.x+ — Jakarta EE 9+ (jakarta.* namespace)
  • Eclipse Jetty 11.x+ — Jakarta EE 9+
  • Wildfly 27.x+ — Jakarta EE 9+

Best practices

  • Use a ServletContextListener to build and register the router at startup, not in the servlet's init().
  • Map the servlet to /* (or / in web.xml) so all requests pass through BareZen routing.
  • Set load-on-startup to 1 so the servlet initializes before the first request.
  • Configure the body limit via init parameter, not via code — keep it deployable without recompilation.

Common issues

"no route table for this servlet"

The servlet was instantiated by the container (no-argument constructor) but no router was set in the ServletContext. Either construct the servlet with new BarezenServlet(router), or set the com.barezen.http.servlet.router attribute before the servlet initializes.

"barezen.maxRequestBodyBytes is 'abc' ... which is not a byte count"

The init parameter value is not a valid number. Check your web.xml or @WebServlet annotation for typos.

405 for methods not listed in HttpServlet

HttpServlet's default service() answers unlisted verbs with 405 before a router is asked. BarezenServlet overrides service() entirely to avoid this — make sure you are using BarezenServlet, not a subclass that calls super.doGet().
