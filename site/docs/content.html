Static content

barezen-content provides StaticContent — one file on disk served as one route, with ETag and conditional GET (304) support.

Module overview

The barezen-content module provides a single class: StaticContent. It creates a Handler for one file on disk. The handler reads the file per request, computes an ETag from the content bytes, and answers 304 to a client that already has the current version.

Design decisions:

  • One handler per file. The router has no wildcard or prefix match, so static files are enumerated — one route per asset.
  • ETag from content, not from the clock. A SHA-256 hash of the bytes changes exactly when the representation does, making it correct across restarts and machines.
  • Whole file in memory. Suitable for stylesheets, favicons, and documentation pages. Not for large files (videos, downloads).
  • Missing file returns 404. No stack trace, no directory listing.

Basic usage

Create a handler for a single file. The content type is inferred from the file extension:

import com.barezen.content.StaticContent;
import java.nio.file.Path;

Handler cssHandler = StaticContent.file(Path.of("public/styles.css"));
Handler jsHandler = StaticContent.file(Path.of("public/app.js"));
Handler imgHandler = StaticContent.file(Path.of("public/logo.png"));

Registering routes

Register each static file as a route. Because the router matches exact paths, you register one route per file:

Router router = Router.builder()
    .route(HttpMethod.GET, "/styles.css",
        StaticContent.file(Path.of("public/styles.css")))
    .route(HttpMethod.GET, "/app.js",
        StaticContent.file(Path.of("public/app.js")))
    .route(HttpMethod.GET, "/logo.png",
        StaticContent.file(Path.of("public/logo.png")))
    .build();

HEAD support

If the representation's length should be knowable to a client that asks with HEAD, register the same handler on both GET and HEAD:

Handler cssHandler = StaticContent.file(Path.of("public/styles.css"));

Router router = Router.builder()
    .route(HttpMethod.GET, "/styles.css", cssHandler)
    .route(HttpMethod.HEAD, "/styles.css", cssHandler)
    .build();

Custom content type

Override the inferred content type by providing it explicitly:

// Serve a .json file as application/manifest+json
Handler manifest = StaticContent.file(
    Path.of("public/manifest.json"),
    "application/manifest+json");

// Serve a .html file with a custom charset
Handler page = StaticContent.file(
    Path.of("public/index.html"),
    "text/html; charset=utf-8");

ETag and conditional GET

The handler computes a strong ETag from the file content using SHA-256 (first 8 bytes, hex-encoded, in quotes). When a client sends If-None-Match with a matching ETag, the handler returns 304 Not Modified with no body.

How it works

  1. Client requests GET /styles.css
  2. Server responds with 200 OK, body, and ETag: "a1b2c3d4e5f60708"
  3. Later, client requests GET /styles.css with If-None-Match: "a1b2c3d4e5f60708"
  4. Server reads the file, computes the same ETag, and returns 304 Not Modified with no body

ETag format

The ETag is a strong tag: the first 8 bytes of the content's SHA-256 hash, hex-encoded, enclosed in double quotes. For example: "a1b2c3d4e5f60708". This provides 2^64 values — collision-free for the set of files one deployment serves.

If-None-Match handling

The handler supports the three shapes defined by RFC 9110:

  • Wildcard. If-None-Match: * matches any ETag.
  • Comma-separated list. If-None-Match: "abc", "def" matches if any tag matches.
  • Weak tags. If-None-Match: W/"abc" is treated the same as "abc" for conditional GET.

Error handling

File not found at construction

If the file does not exist or is not a regular file at construction time, StaticContent.file() throws IllegalArgumentException:

// Throws IllegalArgumentException if the file does not exist
Handler handler = StaticContent.file(Path.of("public/missing.css"));

File disappears at request time

If the file exists at construction but is deleted before a request arrives, the handler returns 404 Not Found — the same plain answer the adapters use for their own 404s. No path is leaked, no stack trace is exposed.

Blank content type

A blank content type is refused at construction. A byte stream with no type is a browser guessing, and the framework refuses to be that browser.

Dynamic asset registration

For a directory of assets, enumerate them at startup:

Path assetsDir = Path.of("public");
Router.Builder builder = Router.builder();

try (DirectoryStream<Path> stream = Files.newDirectoryStream(assetsDir)) {
    for (Path file : stream) {
        if (Files.isRegularFile(file)) {
            String name = file.getFileName().toString();
            String path = "/" + name;
            builder.route(HttpMethod.GET, path, StaticContent.file(file));
        }
    }
}
Router router = builder.build();

What this module does not do

  • No directory listing. A directory would leak the deployment's layout.
  • No streaming. The whole file is read into memory. For large files, write a custom handler.
  • No Last-Modified header. Only ETag is used. A clock-based validator would make the output untestable.
  • No caching headers. The handler does not set Cache-Control. Add a middleware or wrapper handler if you need caching control.

Best practices

  • Register static files at startup, not per request — the handler is stateless and reusable.
  • Use absolute paths or paths relative to the working directory, not classpath resources.
  • For production, consider a reverse proxy (Nginx, Caddy) for static file serving — it is faster and supports range requests.
  • Register HEAD routes alongside GET routes for assets where clients may check size before downloading.

Common issues

"no regular file at /path/to/file"

The file does not exist or is a directory at construction time. Check the path and ensure the file is present before building the router.

"the content type must not be blank"

You passed a blank string as the content type. Provide a valid MIME type or let the framework infer it from the extension.

404 for a file that exists

The file was deleted or moved after the handler was created. The handler re-reads the file per request, so a missing file returns 404. Check the file path and permissions.
