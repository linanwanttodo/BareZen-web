Static content

barezen-content provides StaticContent — one file, on disk or on the classpath, served as one route, with ETag, conditional GET (304) and single byte range support.

Module overview

The barezen-content module provides a single class: StaticContent. It creates a Handler for one file on disk or one classpath resource. The handler reads the content per request, computes an ETag from the bytes, and answers 304 to a client that already has the current version.

Design decisions:

  • One handler per file. The router has no wildcard or prefix match, so static files are enumerated — one route per asset.
  • ETag from content, not from the clock. A SHA-256 hash of the bytes changes exactly when the representation does, making it correct across restarts and machines.
  • Whole file in memory. Suitable for stylesheets, favicons, and documentation pages. Not for large files (videos, downloads).
  • Missing file returns 404. No stack trace, no directory listing.

Basic usage

Create a handler for a single file. The content type is inferred from the file extension:

import com.barezen.content.StaticContent;
import java.nio.file.Path;

Handler cssHandler = StaticContent.file(Path.of("public/styles.css"));
Handler jsHandler = StaticContent.file(Path.of("public/app.js"));
Handler imgHandler = StaticContent.file(Path.of("public/logo.png"));

Registering routes

Register each static file as a route. Because the router matches exact paths, you register one route per file:

Router router = Router.builder()
    .route(HttpMethod.GET, "/styles.css",
        StaticContent.file(Path.of("public/styles.css")))
    .route(HttpMethod.GET, "/app.js",
        StaticContent.file(Path.of("public/app.js")))
    .route(HttpMethod.GET, "/logo.png",
        StaticContent.file(Path.of("public/logo.png")))
    .build();

HEAD support

If the representation's length should be knowable to a client that asks with HEAD, register the same handler on both GET and HEAD:

Handler cssHandler = StaticContent.file(Path.of("public/styles.css"));

Router router = Router.builder()
    .route(HttpMethod.GET, "/styles.css", cssHandler)
    .route(HttpMethod.HEAD, "/styles.css", cssHandler)
    .build();

Custom content type

Override the inferred content type by providing it explicitly:

// Serve a .json file as application/manifest+json
Handler manifest = StaticContent.file(
    Path.of("public/manifest.json"),
    "application/manifest+json");

// Serve a .html file with a custom charset
Handler page = StaticContent.file(
    Path.of("public/index.html"),
    "text/html; charset=utf-8");

ETag and conditional GET

The handler computes a strong ETag from the file content using SHA-256: the complete 32-byte digest as 64 lowercase hex digits, in quotes. On GET and HEAD, a client that sends If-None-Match with a matching tag receives 304 Not Modified with no body.

How it works

  1. Client requests GET /styles.css
  2. Server responds with 200 OK, body, and an ETag such as "ec185bc08f4786af241df127b22ae38c7ed5efc6393649e364daa306c425c0cb"
  3. Later, client requests GET /styles.css with that tag in If-None-Match
  4. Server reads the file, computes the same ETag, and returns 304 Not Modified with the tag and no body

ETag format

The ETag is a strong tag: all 32 bytes of the content's SHA-256 hash, hex-encoded, enclosed in double quotes. The tag is derived only from the bytes, so identical content produces an identical tag across files, restarts and machines. No Content-Length is sent with a 304; the response contract forbids a body for that status.

If-None-Match handling

The handler supports the shapes defined by RFC 9110:

  • Wildcard. If-None-Match: * matches any current representation.
  • Comma-separated list. If-None-Match: "abc", "def" matches if any member matches.
  • Weak tags. If-None-Match: W/"abc" is compared as "abc".
  • Valid tags only. A candidate must be a quoted entity tag, optionally prefixed with W/. Unquoted values, a missing closing quote and lowercase w/ are ignored rather than stripped into a match.
  • Retrieval methods only. A matching tag on POST or any method other than GET and HEAD is ignored; the request gets the ordinary representation, not a 304.

Single byte range

On GET, one bytes range is answered with 206 and the selected bytes, plus Content-Range and the existing content type and ETag:

GET /styles.css
Range: bytes=2-5

206 Partial Content
Content-Range: bytes 2-5/44

bytes=7- and bytes=-3 work as well. A syntactically valid range outside the representation, a zero-length suffix, or any range over an empty representation produces 416 with an empty body and Content-Range: bytes */size.

Malformed syntax, an end before the start, an unknown unit, numeric overflow, a comma-separated set and repeated Range field lines fall back to the complete 200 response. HEAD ignores Range and keeps the full representation length. If-Range enables the range only when its single value exactly equals the current strong ETag; a stale tag, weak tag, HTTP date or repeated field line falls back to 200. If-None-Match is evaluated first, so a matching validator on GET or HEAD still answers 304.

Classpath resources

For assets that ship inside the jar, use StaticContent.resource(ClassLoader, name) or its overload with an explicit content type:

Handler icon = StaticContent.resource(
    getClass().getClassLoader(), "public/favicon.ico");

Handler manifest = StaticContent.resource(
    getClass().getClassLoader(), "public/manifest.json",
    "application/manifest+json");

The name must be relative and must not contain empty, . or .. segments. The bytes are read once at construction and frozen because a jar resource is not a live deployment file; ETag, conditional GET, range and MIME rules are shared with file(...). A missing resource fails construction. There is no classpath scanning, directory route or request-supplied resource name.

Error handling

File not found at construction

If the file does not exist or is not a regular file at construction time, StaticContent.file() throws IllegalArgumentException:

// Throws IllegalArgumentException if the file does not exist
Handler handler = StaticContent.file(Path.of("public/missing.css"));

File disappears at request time

If the file exists at construction but is deleted before a request arrives, the handler returns 404 Not Found — the same plain answer the adapters use for their own 404s. No path is leaked, no stack trace is exposed.

Blank content type

A blank content type is refused at construction. A byte stream with no type is a browser guessing, and the framework refuses to be that browser.

Dynamic asset registration

For a directory of assets, enumerate them at startup:

Path assetsDir = Path.of("public");
Router.Builder builder = Router.builder();

try (DirectoryStream<Path> stream = Files.newDirectoryStream(assetsDir)) {
    for (Path file : stream) {
        if (Files.isRegularFile(file)) {
            String name = file.getFileName().toString();
            String path = "/" + name;
            builder.route(HttpMethod.GET, path, StaticContent.file(file));
        }
    }
}
Router router = builder.build();

What this module does not do

  • No directory listing. A directory would leak the deployment's layout.
  • No streaming. The whole file is read into memory, and a range selects from those bytes. For large files, write a custom handler.
  • No Last-Modified header. Only ETag is used. A clock-based validator would make the output untestable.
  • No multipart ranges. One byte range per GET; a comma-separated set falls back to the complete response.
  • No If-Match or If-Modified-Since. Conditional write preconditions and date validators are out of scope.
  • No caching headers. The handler does not set Cache-Control. Add a middleware or wrapper handler if you need caching control.

Best practices

  • Register static files at startup, not per request — the handler is stateless and reusable.
  • Use absolute paths or paths relative to the working directory for live files; use StaticContent.resource(...) for assets packaged in the jar.
  • The module answers a single byte range, but for large files or heavy static traffic a reverse proxy (Nginx, Caddy) is still the better fit: it streams and never buffers the whole file.
  • Register HEAD routes alongside GET routes for assets where clients may check size before downloading.

Common issues

"no regular file at /path/to/file"

The file does not exist or is a directory at construction time. Check the path and ensure the file is present before building the router.

"the content type must not be blank"

You passed a blank string as the content type. Provide a valid MIME type or let the framework infer it from the extension.

404 for a file that exists

The file was deleted or moved after the handler was created. The handler re-reads the file per request, so a missing file returns 404. Check the file path and permissions.
