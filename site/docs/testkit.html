TestKit

barezen-testkit provides TestServer, TestHttpClient, Assertions, and TestDatabase — tools for integration testing the whole stack.

Module overview

The barezen-testkit module provides tools for integration testing BareZen applications. Unlike unit tests that mock everything, TestKit starts a real HTTP server on a random port and lets you send real HTTP requests to it.

Key types:

TypeRole
TestServerReal HTTP server on a random loopback port
TestHttpClientThin HTTP client for talking to TestServer
TestResponseResponse from TestHttpClient: status, headers, body
AssertionsFluent assertions for responses, counts, and security identity
TestDatabaseIn-memory H2 database for tests
PrincipalFixtureTest fixture for security identity assertions

TestServer

TestServer wraps JdkHttpServerAdapter on a random loopback port. It binds the real adapter to 127.0.0.1 on port 0, so the OS hands back an unused port — parallel test classes never fight over a fixed number.

Basic usage

import com.barezen.testkit.TestServer;
import com.barezen.testkit.Assertions;

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", (req, params) ->
        new Response(200, Headers.of("Content-Type", "text/plain"), "OK".getBytes()))
    .build();

try (TestServer server = TestServer.start(router)) {
    TestResponse response = server.client().get("/health");
    Assertions.assertThat(response).statusIs(200).bodyIs("OK");
}  // Server stops and port is released automatically

API methods

MethodDescription
start(Router)Starts a server on a random port. Returns a started server.
port()Returns the bound port (always positive once started).
baseUri()Returns the base URI, e.g., http://127.0.0.1:45678.
client()Returns a TestHttpClient wired to this server.
isRunning()Returns true if the server is still serving.
close()Stops the server. Idempotent — safe to call twice.

Try-with-resources

Always use try-with-resources so the port is always released:

try (TestServer server = TestServer.start(router)) {
    // Run tests
}  // Port is released even if a test fails

TestHttpClient

TestHttpClient is a thin HTTP client for talking to a TestServer. It resolves paths against the server's base URI and returns TestResponse objects.

HTTP verb methods

Every verb the framework routes has a direct method:

TestHttpClient client = server.client();

// GET
TestResponse get = client.get("/users");

// HEAD
TestResponse head = client.head("/users");

// POST with body
TestResponse post = client.post("/users", "{\"name\":\"Alice\"}");

// PUT with body
TestResponse put = client.put("/users/1", "{\"name\":\"Bob\"}");

// PATCH with body
TestResponse patch = client.patch("/users/1", "{\"name\":\"Carol\"}");

// DELETE
TestResponse delete = client.delete("/users/1");

// OPTIONS
TestResponse options = client.options("/users");

Custom requests

For requests with custom headers or any method not covered by the shortcuts:

TestResponse response = client.request(HttpMethod.GET, "/users")
    .header("Accept", "application/json")
    .header("Authorization", "Bearer token123")
    .send();

Request builder

MethodDescription
header(String name, String value)Adds a request header. Chainable.
body(String body)Sets the request body as UTF-8 text.
send()Sends the request and returns the response.

Timeout

Requests have a 10-second timeout. If the server does not respond within 10 seconds, a TestRequestFailedException is thrown.

TestResponse

TestResponse carries the status code, headers, and body from the server:

MethodDescription
status()Returns the HTTP status code (e.g., 200, 404).
header(String name)Returns the first value of a header as Optional<String>. Case-insensitive name matching.
body()Returns the response body as a UTF-8 string.
bodyBytes()Returns the response body as raw bytes.

Assertions

Assertions provides fluent assertions for BareZen integration tests. Every failure throws an AssertionError showing both what was expected and what was actually returned.

Response assertions

Assertions.assertThat(response)
    .statusIs(200)
    .headerIs("Content-Type", "application/json")
    .bodyIs("{\"message\":\"ok\"}")
    .bodyContains("\"id\":1");

Assertion methods

MethodDescription
statusIs(int)Asserts the status code.
headerIs(String, String)Asserts a header's exact value.
headerExists(String)Asserts a header is present, whatever its value.
bodyIs(String)Asserts the body equals the expected string (UTF-8).
bodyContains(String)Asserts the body contains the expected substring.
jsonStringIs(String path, String expected)Asserts a JSON path's string value. Dot-separated path.
jsonNumberIs(String path, Number expected)Asserts a JSON path's numeric value.

Count assertions

Assert on a handler's invocation count:

CountingHandler handler = new CountingHandler((req, params) ->
    new Response(200, Headers.empty(), null));

// ... invoke the handler ...

Assertions.assertThat(handler.count()).isEqualTo(1);

Identity assertions

Assert on the security identity a fixture recorded:

PrincipalFixture fixture = new PrincipalFixture();
// ... wire fixture into security middleware ...

Assertions.assertThat(fixture.seen()).hasName("alice");

TestDatabase

TestDatabase provides an in-memory H2 database for tests:

try (TestDatabase testDb = TestDatabase.create()) {
    Database db = testDb.database();

    // Run migrations
    Migrator migrator = new Migrator(db);
    migrator.migrate(List.of(createUsersTable));

    // Use the database in your tests
    db.executeUpdate("INSERT INTO users (name, email) VALUES (?, ?)",
        "Alice", "alice@example.com");

    List<User> users = db.query(
        "SELECT id, name, email FROM users",
        userMapper);
}

API methods

MethodDescription
create()Creates a new in-memory H2 database. Auto-closes on try-with-resources end.
database()Returns the Database instance for queries and updates.
dataSource()Returns the underlying DataSource if you need it.
close()Closes the database connection. Idempotent.

Complete test example

import com.barezen.testkit.*;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

class UserApiTest {

    @Test
    void createUser() {
        // 1. Set up in-memory database
        try (TestDatabase testDb = TestDatabase.create()) {
            Database db = testDb.database();

            // 2. Run migrations
            new Migrator(db).migrate(List.of(createUsersTable));

            // 3. Build application components
            UserRepository repo = new UserRepository(db);
            Handler createUser = (req, params) -> {
                Map<String, String> body = parseJson(req.body());
                User user = repo.create(
                    body.get("name"),
                    body.get("email"),
                    "hashed-password");
                return new Response(201,
                    Headers.of("Content-Type", "application/json"),
                    ("{\"id\":" + user.id() + "}").getBytes());
            };

            // 4. Build router
            Router router = Router.builder()
                .route(HttpMethod.POST, "/users", createUser)
                .build();

            // 5. Start test server
            try (TestServer server = TestServer.start(router)) {
                // 6. Send request
                TestResponse response = server.client()
                    .post("/users", "{\"name\":\"Alice\",\"email\":\"alice@example.com\"}");

                // 7. Assert
                Assertions.assertThat(response)
                    .statusIs(201)
                    .headerIs("Content-Type", "application/json")
                    .bodyContains("\"id\":");
            }
        }
    }
}

Best practices

  • Use try-with-resources for TestServer and TestDatabase to ensure cleanup.
  • Use TestDatabase for tests that need a database — it is isolated per test.
  • Use Assertions.assertThat() for readable test failures that show expected vs actual.
  • Run tests in parallel — each TestServer uses a random port, so they do not conflict.
  • For security tests, use Authentication.bearer() for simple token-based auth in tests.

Common issues

"Connection refused"

The test server was not started or was already closed. Make sure TestServer.start() is called before sending requests, and that the server is not closed before the test completes.

"TestRequestFailedException"

The request could not be completed — connection refused, timeout, or interruption. Check that the server is running and the path is correct.

"expected status 200 but got 404"

The route was not registered or the path does not match. Check the router configuration and the request path.
