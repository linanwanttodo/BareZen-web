Security module

barezen-security provides authentication, authorization, session management, and password hashing — all pluggable and request-scoped.

Module overview

The barezen-security module provides a complete security layer for BareZen applications. It is organized around three core concerns:

ConcernTypesDescription
AuthenticationAuthentication, AuthenticationResult, CredentialVerifying who the client claims to be
AuthorizationAuthorization, Permission, PrincipalDeciding what an authenticated identity may do
SessionsSessionStore, SessionTokenStateful session management with tokens
PasswordsPasswordHasherPBKDF2-HMAC-SHA256 password hashing
MiddlewareSecurityMiddleware, SecurityContext, SecuredHandlerWiring authentication and authorization into the request pipeline

Authentication

Authentication answers "who is this client?" The Authentication interface is a functional interface with one method:

@FunctionalInterface
public interface Authentication {
    AuthenticationResult authenticate(Credential credential);
}

AuthenticationResult — three states

HTTP security has three answers, and the result is a sealed hierarchy to make all three explicit:

StateFactoryHTTP responseMeaning
AuthenticatedAuthenticationResult.authenticated(principal)Pass throughClient proved an identity
FailureAuthenticationResult.failure("reason")401 UnauthorizedClient offered a credential that did not verify
AnonymousAuthenticationResult.anonymous()Depends on authorizationClient offered no credential at all

The distinction between Failure and Anonymous is critical: a bad credential is a request that failed to prove anything (401), while no credential is a valid request that may or may not be allowed (401 or 403 depending on authorization).

Credential

A Credential is a record with two fields: scheme (e.g., "Bearer", "Basic") and value (the token or encoded credentials). The middleware extracts the credential from the Authorization header and passes it to the authentication implementation.

Built-in authentication implementations

Anonymous authentication

Trusts nothing — every request is anonymous. Used as the default when no authentication is configured:

Authentication auth = Authentication.anonymous();

Bearer token authentication

Matches a fixed scheme and value. Useful for tests and simple API key setups:

Principal admin = Principal.of("admin");
Authentication auth = Authentication.bearer("Bearer", "secret-token-123", admin);

Custom authentication

Implement Authentication to verify credentials against a database, external service, or token issuer:

Authentication auth = (credential) -> {
    if (credential == null) {
        return AuthenticationResult.anonymous();
    }
    // Look up user by token
    Optional<User> user = userRepository.findByToken(credential.value());
    if (user.isPresent()) {
        return AuthenticationResult.authenticated(
            Principal.of(user.get().username()));
    }
    return AuthenticationResult.failure("invalid token");
};

Authorization

Authorization answers "is this identity allowed to do this?" The Authorization interface is a functional interface:

@FunctionalInterface
public interface Authorization {
    Decision authorize(Principal principal, Permission required);
}

Decision

Two states: ALLOW (pass through) or DENY (403 Forbidden). The default is deny — an identity without an explicit grant does not have the permission.

Built-in authorization implementations

Allow all

Every authenticated identity has every permission. Useful for tests:

Authorization authz = Authorization.allowAll();

Deny all

No authenticated identity has any permission. Used as the default when no authorization is configured:

Authorization authz = Authorization.denyAll();

Table-based authorization

A fixed table maps principals to their permissions:

Permission READ = Permission.of("read:users");
Permission WRITE = Permission.of("write:users");

Principal alice = Principal.of("alice");
Principal bob = Principal.of("bob");

Authorization authz = Authorization.of(Map.of(
    alice, Set.of(READ, WRITE),
    bob, Set.of(READ)));

// alice can read and write
// bob can read only
// anyone else is denied

Permission

A Permission is an immutable string identifier. Use dot-separated names for hierarchy:

Permission.READ_USERS = Permission.of("read:users");
Permission.WRITE_USERS = Permission.of("write:users");
Permission.DELETE_USERS = Permission.of("delete:users");

SecurityContext

A SecurityContext is a request-scoped value that carries the authentication result. It is not a thread-local, not a session, and not a cache:

public record SecurityContext(AuthenticationResult authentication) {
    public Optional<Principal> principal();
    public boolean isAuthenticated();
}

The context is immutable because a request's security answer is decided once. A handler cannot change the identity of the request it is answering.

SecuredHandler

Wrap a handler with security requirements using SecuredHandler:

Handler inner = (req, params) -> {
    // This code runs only if authentication and authorization pass
    return new Response(200, ...);
};

// Require authentication (any authenticated user)
Handler secured = SecuredHandler.authenticated(inner);

// Require a specific permission
Handler secured = SecuredHandler.require(inner, Permission.of("write:users"));

SecurityMiddleware

The middleware wires authentication and authorization into the request pipeline. It implements RouteContributor and LifecycleParticipant:

SecurityMiddleware middleware = SecurityMiddleware.create(
    Authentication.bearer("Bearer", "secret", Principal.of("admin")),
    Authorization.allowAll());

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", healthHandler)
    .contributing(List.of(middleware))
    .build();

What the middleware does

  1. Extracts the Authorization header from the request
  2. Creates a Credential (or null if absent)
  3. Calls Authentication.authenticate(credential)
  4. If Failure, returns 401 Unauthorized
  5. If Authenticated and the handler requires a permission, calls Authorization.authorize()
  6. If authorization denies, returns 403 Forbidden
  7. Creates a SecurityContext and passes it to the handler

Session management

SessionStore provides in-memory session management. Sessions are keyed by a random token and expire after a configured duration.

Creating a session

SessionStore store = SessionStore.standard();

// After successful login:
SessionStore.Session session = store.create(
    Principal.of("alice"),
    Duration.ofHours(24));

// Return the token to the client (e.g., in a Set-Cookie header)
String token = session.token().value();

Looking up a session

Optional<SessionStore.Session> session = store.lookup(token);
if (session.isPresent()) {
    Principal principal = session.get().principal();
    // Session is valid and not expired
} else {
    // Token is unknown or expired
}

Invalidating a session (logout)

boolean removed = store.invalidate(token);

Rotating a session

Rotate creates a new token for the same principal, invalidating the old one. Use this after password changes or privilege escalation:

Optional<SessionStore.Session> newSession = store.rotate(oldToken, Duration.ofHours(24));

Session token

A SessionToken is a 32-byte random value encoded as URL-safe Base64. It carries an expiration time and can be checked for expiry:

SessionToken token = session.token();
boolean expired = token.isExpired(Clock.systemUTC().instant());

Password hashing

PasswordHasher uses PBKDF2 with HMAC-SHA-256. The default iteration count is 600,000 (OWASP 2023 recommendation).

Hashing a password

PasswordHasher hasher = PasswordHasher.standard();

// Hash a password for storage
String hash = hasher.hash("user-password");
// Format: PBKDF2WithHmacSHA256$600000$<base64-salt>$<base64-derived-key>

// Store the hash in your database
userRepository.save(username, hash);

Verifying a password

// Retrieve the stored hash
String storedHash = userRepository.findHash(username);

// Verify
if (hasher.verify("user-password", storedHash)) {
    // Password matches
} else {
    // Password does not match
}

Encoded format

The hash is self-describing: algorithm$iterations$salt$derivedKey, all Base64-encoded. This means:

  • The iteration count is stored in the hash, so you can change the default without invalidating old hashes.
  • A malformed hash is rejected as a verification failure, not as an exception.
  • The raw password is never stored, never logged, and never returned.

Test-friendly hashing

For tests, use a lower iteration count and a fixed random source:

PasswordHasher testHasher = PasswordHasher.of(
    1000, new SecureRandom(42));

Complete example: Login flow

// 1. Set up password hashing
PasswordHasher hasher = PasswordHasher.standard();

// 2. Set up session store
SessionStore sessionStore = SessionStore.standard();
Duration sessionDuration = Duration.ofHours(24);

// 3. Authentication: verify username/password from request body
Authentication auth = (credential) -> {
    if (credential == null) {
        return AuthenticationResult.anonymous();
    }
    // Parse username:password from Basic auth or custom body
    String[] parts = decodeCredential(credential);
    String username = parts[0];
    String password = parts[1];

    Optional<String> storedHash = userRepository.findHash(username);
    if (storedHash.isPresent() && hasher.verify(password, storedHash.get())) {
        return AuthenticationResult.authenticated(Principal.of(username));
    }
    return AuthenticationResult.failure("invalid credentials");
};

// 4. Authorization
Authorization authz = Authorization.of(Map.of(
    Principal.of("admin"), Set.of(
        Permission.of("read:users"),
        Permission.of("write:users"))));

// 5. Create middleware
SecurityMiddleware middleware = SecurityMiddleware.create(auth, authz);

// 6. Login handler
Handler login = (req, params) -> {
    // Parse username and password from request body
    Map<String, String> body = parseJson(req.body());
    String username = body.get("username");
    String password = body.get("password");

    Optional<String> storedHash = userRepository.findHash(username);
    if (storedHash.isPresent() && hasher.verify(password, storedHash.get())) {
        SessionStore.Session session = sessionStore.create(
            Principal.of(username), sessionDuration);
        return new Response(200,
            Headers.of("Content-Type", "application/json")
                .with("Set-Cookie", "session=" + session.token().value()),
            "{\"status\":\"ok\"}".getBytes());
    }
    return new Response(401,
        Headers.of("Content-Type", "application/json"),
        "{\"error\":\"invalid credentials\"}".getBytes());
};

// 7. Register routes
Router router = Router.builder()
    .route(HttpMethod.POST, "/login", login)
    .route(HttpMethod.DELETE, "/logout", logoutHandler)
    .contributing(List.of(middleware))
    .build();

Best practices

Authentication

  • Always return one of the three states — never throw from authenticate() for expected failures.
  • Use Failure for bad credentials, Anonymous for missing credentials.
  • Never log the raw credential value.

Authorization

  • Default to deny — an unconfigured setup should not be silently permissive.
  • Use descriptive permission names: read:users, write:users, delete:users.
  • Anonymous requests are denied by the middleware before authorization is called.

Sessions

  • Use short session durations (1-24 hours) for sensitive applications.
  • Rotate sessions after password changes or privilege escalation.
  • Sessions are in-memory only — a server restart invalidates all sessions.
  • For distributed deployments, use an external session store (Redis, database).

Passwords

  • Always use PasswordHasher — never store plain-text passwords.
  • Use the default iteration count (600,000) for production.
  • Use a lower iteration count (1,000) only for tests.
  • The hash format is self-describing — you can change the iteration count over time.

Common issues

"401 vs 403 confusion"

401 means "you are not authenticated" — the client should provide credentials. 403 means "you are authenticated but not authorized" — the client's identity does not have the required permission. Use Failure for 401 and DENY for 403.

"Session expired but token still valid"

SessionStore.lookup() checks expiry automatically. If a token is found but expired, it is removed and Optional.empty() is returned. No manual expiry check is needed.

"Password hash verification is slow"

This is intentional. PBKDF2 with 600,000 iterations is designed to be slow to resist brute-force attacks. If login is too slow, check that the server has adequate CPU resources, not the iteration count.

"SecurityContext is null in my handler"

The SecurityContext is created by the middleware. Make sure the middleware is registered as a RouteContributor and the handler is wrapped with SecuredHandler.
