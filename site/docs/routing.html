Routing & HTTP

The router answers one question. The server decides what goes on the wire. Keeping those apart is why a second server was a module and not a rewrite.

What a pattern may be

A route is a method, a raw path pattern and a handler. A pattern is a literal path or a segment that is exactly {name}, capturing one non-empty raw segment. There is no wildcard, no regex, no optional segment, no repeated segment and no prefix match, and each is refused by name in the build (no_preemptive_routing_or_middleware_types, ADR-0019 §19) rather than left unimplemented by accident.

The reason is one sentence: a matcher that accepts a prefix makes GET /a/b match two routes, and something then has to decide which one wins. That something is a precedence rule, and precedence is an ordering question the router exists not to ask.

Optional<RouteMatch> match  = routes.match(request);      // the question
Set<HttpMethod>   allowed = routes.methodsFor("/users/7"); // empty means 404, non-empty means 405
Router frozen    = routes.build();                        // List.copyOf: no view of a growing builder

A duplicate — same method, same shape — is refused at registration, never resolved by "last one wins". That single decision is what lets a plugin contribute routes without an application having to reason about plugin order.

Commitment matters as much as the status: once bytes are on the wire there is no second answer to send, so a write-side failure is logged and abandoned rather than turned into a 500 that could not be delivered (ADR-0023 §6).

Framing, HEAD and 304

  • A Response refuses Content-Length and Transfer-Encoding, and a duplicated framing header is refused even when its two values agree (ADR-0027 §5, ADR-0029).
  • Which handler runs follows the folded method; which bytes go on the wire follows the raw token the server compares exactly. So HEAD /doc states the length of the body it does not send, and a head /doc token gets the body its representation has. It was measured before it was decided — ADR-0028 records the Temurin 17.0.20.1+1 and 21.0.12.1+1 outputs being diffed, because the earlier rule produced a false Content-Length: 0.
  • A 304 carries no Content-Length. The decision was deferred until something could know the stored representation's size; when StaticContent arrived and did know it, the decision was re-measured over a socket and kept (ADR-0029 D1, ADR-0051).
  • Statuses HTTP gives no body to are refused one at construction, rather than being silently dropped at the socket.

Bodies are bytes

A request body is read fully and bounded; a response body is a byte[]. Streaming was measured against three named conditions and not built, because a live writer would break the framing table above — including the HEAD row a static file now relies on (ADR-0030, ADR-0051). The default bound is one mebibyte in both servers, so a client cannot send more content by choosing a deployment model.

Two servers, one table: the reference page lists what is identical across them and the three things a servlet container refuses before BareZen can see them.
