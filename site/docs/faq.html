Frequently asked questions

Common questions about BareZen's design, architecture, and usage patterns.

Design decisions

Why no annotations or reflection?

BareZen uses explicit, reflection-free dependency injection (ADR-0014). There are no @Inject, @Component, or @Autowired annotations. An application states what it has in code, and the framework works out the creation order. This makes dependencies visible at the call site, greppable, and refactorable with standard IDE tools.

Why is the router immutable?

The router is immutable after build() (ADR-0019). There is no unregister(), replace(), or reload(). This means a request thread cannot race a registration — the race does not exist. If you need to change routes at runtime, build a new router and swap the reference atomically.

Why no wildcard routes like /assets/*?

The router answers "which handler is this request for" using exact segments or {name} parameters. There is no wildcard, prefix match, or multi-segment capture (ADR-0019 §5, §19). For static files, enumerate them — one route per asset. This keeps the router a simple, one-question component.

Why is the request body in memory?

Request.body() returns byte[] (ADR-0030). A streaming body would require the contract to say who closes the stream, what happens when a handler returns without reading it, and what happens when a handler hands it to another thread. None of those questions has an answer that does not depend on a server. For large file uploads, use the adapter's request body limit configuration.

Why no Content-Length in Response?

Content-Length and Transfer-Encoding are not a handler's to write (ADR-0027). These fields describe how many bytes follow the header block — a fact about the connection, not the application's answer. Only the adapter writing bytes can state them truly. The adapter derives Content-Length from the body bytes.

Why two-phase startup?

Startup runs in two global phases (ADR-0003): initialize then start. This guarantees that a participant that makes work observable (such as an HTTP server binding a port) does so only after every earlier participant has finished its setup. Interleaving the two phases per component cannot express this invariant.

Why is SecurityContext not a ThreadLocal?

A thread is not a request. A server thread may handle many requests, and a request may not complete on the thread that started it. A ThreadLocal would leak one request's identity into another. The context is request-scoped and passed through the middleware chain.

Can I use both adapters in the same application?

Yes, but they would be separate servers on different ports. Typically you choose one: JDK adapter for embedded deployments, Servlet for container deployments.

How do I add middleware?

BareZen does not have a generic middleware chain. Instead, use these patterns:

  • RouteContributor — for adding routes from plugins.
  • Handler wrapping — wrap a handler to add cross-cutting behavior (logging, timing, CORS).
  • SecurityMiddleware — for authentication and authorization.
// Example: Logging wrapper
Handler logging(Handler inner) {
    return (req, params) -> {
        long start = System.nanoTime();
        try {
            return inner.handle(req, params);
        } finally {
            long elapsed = System.nanoTime() - start;
            System.out.println(req.method() + " " + req.path() + " " + elapsed + "ns");
        }
    };
}

How do I handle CORS?

Wrap your handler to add CORS headers:

Handler cors(Handler inner) {
    return (req, params) -> {
        if (req.method() == HttpMethod.OPTIONS) {
            return new Response(204, Headers.empty(), null);
        }
        Response response = inner.handle(req, params);
        // Add CORS headers to the response
        return response; // With additional headers
    };
}

How do I override configuration?

Configuration layers are ordered weakest-first: properties file < environment variables < system properties. To override:

# Properties file (lowest priority)
server.port=8080

# Environment variable (medium priority)
export BAREZEN_HTTP_JDK_TLS_KEYSTOREPATH=/path/to/keystore.p12

# JVM system property (highest priority)
java -Dserver.port=9090 -jar app.jar

Database

Which databases are supported?

Any JDBC-compliant database. The framework has been tested with H2 (in-memory), PostgreSQL, and MySQL. The Database class is product-agnostic — it takes a DataSource and never names a driver.

How do I use connection pooling?

Create a pooled DataSource and pass it to Database:

HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:postgresql://localhost/mydb");
config.setUsername("user");
config.setPassword("password");
DataSource ds = new HikariDataSource(config);
Database db = new Database(ds);

Can I nest transactions?

No. Each transaction() call opens a new connection on a new thread. Nesting is not supported (ADR-0039). If you need savepoints, use the underlying JDBC connection directly inside a transaction callback.

Security

What's the difference between 401 and 403?

  • 401 Unauthorized — The client is not authenticated. The credential was bad or missing. Return AuthenticationResult.failure().
  • 403 Forbidden — The client is authenticated but not authorized. The identity does not have the required permission. Return Authorization.Decision.DENY.

How do I implement JWT authentication?

Implement the Authentication interface:

Authentication jwtAuth = (credential) -> {
    if (credential == null || !credential.scheme().equals("Bearer")) {
        return AuthenticationResult.anonymous();
    }
    try {
        Claims claims = Jwts.parser()
            .setSigningKey(secret)
            .parseClaimsJws(credential.value())
            .getBody();
        String username = claims.getSubject();
        return AuthenticationResult.authenticated(Principal.of(username));
    } catch (JwtException e) {
        return AuthenticationResult.failure("invalid token");
    }
};

Are sessions distributed?

No. SessionStore is in-memory only. A server restart invalidates all sessions. For distributed deployments, implement your own session store backed by Redis or a database.

Testing

Why use TestServer instead of mocking?

TestServer starts a real HTTP server on a random port. An integration test that used a fake server would only prove the fake works. The bytes that cross the socket are the bytes the production adapter produces.

Can I run tests in parallel?

Yes. Each TestServer uses a random port (port 0), so parallel test classes never fight over a fixed number.

Deployment

How do I deploy to production?

Two options:

  1. Embedded — Package as a JAR with a main() method. Use JdkHttpServerAdapter with configuration from application.properties.
  2. Container — Package as a WAR. Use BarezenServlet deployed to Tomcat, Jetty, or Wildfly.

How do I enable HTTPS in production?

For JDK adapter, configure the keystore in application.properties:

barezen.http.jdk.tls.keystorePath=/path/to/keystore.p12
barezen.http.jdk.tls.keystorePassword=changeit

For Servlet deployment, configure TLS at the container level (Tomcat's server.xml, Jetty's etc/jetty-ssl.xml).

How do I handle graceful shutdown?

The LifecycleOrchestrator registers a JVM shutdown hook by default. It gives in-flight requests 3 seconds to complete. For container deployment, turn off the shutdown hook:

LifecycleOrchestrator.builder()
    .registerShutdownHook(false)
    .build();

Performance

Does BareZen use virtual threads?

On Java 21+, yes — by default. The JDK adapter auto-detects virtual thread support and uses them. On Java 17, it falls back to platform threads.

What is the request body limit?

Default is 1 MB. Configure it via barezen.http.jdk.maxRequestBodyBytes (JDK adapter) or barezen.maxRequestBodyBytes init parameter (Servlet). Requests exceeding the limit are rejected with 413 before the handler runs.

Is StaticContent suitable for large files?

No. StaticContent reads the whole file into memory. It is designed for stylesheets, JavaScript, images, and small documents. For large files (videos, downloads), write a custom handler that streams the response.

What if I need a feature BareZen doesn't have?

BareZen is designed to be minimal. If you need a feature not built in:

  • Write a handler wrapper for cross-cutting concerns (logging, CORS, rate limiting).
  • Write a RouteContributor for plugin-style route additions.
  • Use a standard Java library (Jackson for JSON, HikariCP for pooling) alongside BareZen.

The framework provides the contract (Request, Response, Handler, Router) and lets you fill in the rest.
