两个服务器，一张表

两边被断言一致的部分：六种应答和它们的 body、Allow 的排序、分帧（有 body 才给长度，204/304 不给）、 HEAD 声明一个它并不发送的长度、小写 token 带来的不对称、1 MiB 的默认上限， 以及 handler 的异常进日志而不是进 socket。

三件 servlet 容器抢在 BareZen 能回答之前就替它决定了的事，实测并记录下来了，没有被抹平：路径里百分号编码的斜杠、 比声明的 Content-Length 更短的 body，以及 TRACE —— 三者都带着容器自己的 HTML 错误页回来 （其中一个还带着异常报告），而容器还会重写 Content-Type 参数里的空白。 替换这些页面属于部署策略，作为未完成工作点名（ADR-0049 §7）。

决策，按编号

五十四份 ADR 在 docs/adr/ 里，每份一个决策，都写明它拒绝了哪些替代方案、哪些测试证明它、 一份非目标清单，以及一个重新开启的触发条件。跟你刚读这几页直接相关的： 0003 两阶段启动 0006 不做 service locator 0013 配置在装配期定 0014 显式依赖注入 0016 插件就是参与者 0018 HTTP 是契约 0019 路由语义 0024 服务器生命周期 0027/0028/0029 分帧、HEAD、304 0031 body 上限 0032 class-major 契约 0033–0037 安全 0038–0040 数据 0041–0043 插件与 OpenAPI 0044 TestKit 0045 示例 0047 扩展点 0048 发现机制 0049 servlet 0050 TLS 0051 静态内容 0052 这个站点 0053 两种语言 0054 静态文件

仍然敞开的，按名字

  • 路由枚举。一条路由被声明两次 —— 一次作为路由、一次作为 OpenAPI 元数据， 因为路由表不对外提供查看的答案。修法需要给 ADR-0019 §19 打补丁，并配一个测试来证明"合并这一步"不是拿到的替代品 （ADR-0047、ADR-0042）。
  • 给被发现的插件注入。被发现的插件什么都不需要；一旦需要点什么，答案是显式的工厂， 不是查找（ADR-0048）。
  • 第二个扩展点。事件总线自 2.6 之后没有消费者，它是指名的候选（ADR-0047）。
  • 流式 body、range 请求、条件 Last-Modified、缓存策略、错误页的表示形式、mTLS、 嵌入式容器适配器、许可证文件、已发布的构件。每一个都是一条带着触发条件的推迟， 写在它旁边那份记录里；没有一个只是 TODO。
  • 翻译对齐。中文页与英文页一对一手工维护，没有机器翻译，也没有翻译记忆库； 测试只钉住"每个文件都有对应页、每对链接都双向可达"（ADR-0053）。

预览与部署这份文档

./scripts/check-site.sh                    # 每个链接在磁盘上都能解析，两种语言逐页配对
python3 -m http.server 8000                # 预览 http://127.0.0.1:8000/site/

这棵树就是一堆相对地址的文件，所以任何静态托管都能原样部署：GitHub Pages 就是 Settings → Pages → Deploy from a branch，选 main 分支和 /site 目录。 这里之所以不需要我们自己的服务器，理由就藏在"链接全是相对路径"这件事里：项目站的地址在 /仓库名/site/ 之下，以 /assets/… 开头的地址会解析到站点之上，直接 404。 静态托管不给的东西也一并写清楚：没有条件 GET，没有由插件生成的 /openapi.json， URL 保留文件自己的 .html 后缀（ADR-0054）。

构建与验证

mvn -o -B -ntp clean verify          # 单元、集成、架构、覆盖率门槛
./scripts/check-jdk-baseline.sh      # 声明的 release 仍然是 17
./scripts/check-class-major.sh       # 每个产出的 class 文件都是 major 61
./scripts/check-site.sh              # 文档树自身一致

JDK 17 是兼容基线，JDK 21 及以上是建议的运行环境；虚拟线程是启动时探测到的运行时能力， 从来不是一个构建变体（ADR-0002、ADR-0010）。
