Servlet 集成

barezen-http-servlet 提供 BarezenServlet，一个标准的 HttpServlet，在 Tomcat、Jetty 或 Wildfly 内部分发到 BareZen Router。

模块概览

barezen-http-servlet 模块将 BareZen 与 Jakarta Servlet API 集成。你不是运行自己的 HTTP 服务器，而是将标准 WAR 文件部署到现有的 servlet 容器。容器拥有端口、线程池、执行器和生命周期 — BareZen 只提供路由和处理程序分发。

BarezenServlet 不是 HttpServerAdapter。适配器启动、停止、报告其绑定端口，且无法重启。由它不控制的容器实例化的 servlet 无法诚实地回答 port() 或 isRunning()（ADR-0049）。

两种部署模式

因为容器实例化它部署的内容，有两种传递路由表的方式：

1. 编程嵌入

应用构建路由器并将其传递给 servlet 构造函数：

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", (req, params) ->
        new Response(200, Headers.of("Content-Type", "text/plain"), "OK".getBytes()))
    .build();

BarezenServlet servlet = new BarezenServlet(router);
// 以编程方式将 servlet 注册到容器

2. 声明式部署（web.xml 或 @WebServlet）

容器通过其无参构造函数实例化 servlet。应用的 ServletContextListener 在启动时将路由器设置为上下文属性：

// 在你的 ServletContextListener 中：
public void contextInitialized(ServletContextEvent event) {
    Router router = Router.builder()
        .route(HttpMethod.GET, "/health", healthHandler)
        .build();
    event.getServletContext().setAttribute(
        BarezenServlet.ROUTER_ATTRIBUTE, router);
}

web.xml 配置

<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         version="6.0">

  <servlet>
    <servlet-name>barezen</servlet-name>
    <servlet-class>com.barezen.http.servlet.BarezenServlet</servlet-class>
    <init-param>
      <param-name>barezen.maxRequestBodyBytes</param-name>
      <param-value>5242880</param-value>
    </init-param>
    <load-on-startup>1</load-on-startup>
  </servlet>

  <servlet-mapping>
    <servlet-name>barezen</servlet-name>
    <url-pattern>/</url-pattern>
  </servlet-mapping>

</web-app>

@WebServlet 注解

@WebServlet(
    urlPatterns = "/*",
    initParams = @WebInitParam(
        name = "barezen.maxRequestBodyBytes",
        value = "5242880"))
public class MyServlet extends BarezenServlet {
}

配置

servlet 在 init() 期间读取一次其配置：

初始化参数类型默认值描述
barezen.maxRequestBodyByteslong1 MB（1,048,576 字节）最大请求主体大小。超过此限制的请求以 413 拒绝。

如果参数存在但不是有效的数字，部署以 ServletException 失败，命名参数和找到的值。

ServletContext 属性

对于声明式部署，必须在 servlet 初始化之前将路由器放在属性名 com.barezen.http.servlet.router（可作为 BarezenServlet.ROUTER_ATTRIBUTE 访问）下。

错误响应

与 JDK 适配器相同 — 切换服务器不应改变客户端读取的内容（ADR-0023）：

状态码何时
400 Bad Request格式错误的请求目标或主体从未到达。
404 Not Found没有路由匹配请求方法和路径。
405 Method Not Allowed路径存在路由但不是请求的方法。Allow 头部列出允许的方法。
413 Payload Too Large请求主体超过配置的限制。
500 Internal Server Error处理程序抛出异常。堆栈跟踪进入日志，不进入客户端。

线程安全

一个 servlet 实例并发地服务每个请求。它除了路由表和一个数字（主体限制）外不保留任何内容，所以没有每请求状态会泄漏。servlet 规范保证 init() 在第一次 service() 调用之前发生，使这两个字段无需锁即可安全读取。

servlet 不做的事情

  • 它不解析 HTTP — 容器在请求对象存在之前拒绝格式错误的请求行。
  • 它不回答 OPTIONS * — 容器在路由之前解析了目标。
  • 它不为每个请求记录一行 — 访问日志是容器的工作。
  • 它不捕获 Error — handler 内部的 OutOfMemoryError 不是 500 回答的条件。

支持的容器

servlet 模块依赖 Jakarta Servlet API（jakarta.servlet）。已使用以下容器测试：

  • Apache Tomcat 10.x+ — Jakarta EE 9+（jakarta.* 命名空间）
  • Eclipse Jetty 11.x+ — Jakarta EE 9+
  • Wildfly 27.x+ — Jakarta EE 9+

最佳实践

  • 使用 ServletContextListener 在启动时构建和注册路由器，而不是在 servlet 的 init() 中。
  • 将 servlet 映射到 /*（或 web.xml 中的 /），以便所有请求通过 BareZen 路由。
  • 将 load-on-startup 设置为 1，以便 servlet 在第一个请求之前初始化。
  • 通过初始化参数配置主体限制，而不是通过代码 — 使其无需重新编译即可部署。

常见问题

"no route table for this servlet"

servlet 由容器实例化（无参构造函数），但 ServletContext 中未设置路由器。要么用 new BarezenServlet(router) 构造 servlet，要么在 servlet 初始化之前设置 com.barezen.http.servlet.router 属性。

"barezen.maxRequestBodyBytes is 'abc' ... which is not a byte count"

初始化参数值不是有效的数字。检查你的 web.xml 或 @WebServlet 注解中的拼写错误。

HttpServlet 中未列出的方法出现 405

HttpServlet 的默认 service() 在未列出动词上回答 405，而不询问路由器。BarezenServlet 完全覆盖 service() 以避免此问题 — 确保你使用的是 BarezenServlet，而不是调用 super.doGet() 的子类。
