静态内容

barezen-content 提供 StaticContent — 磁盘上的一个文件作为一条路由提供，支持 ETag 和条件 GET（304）。

模块概览

barezen-content 模块提供一个类：StaticContent。它为磁盘上的一个文件创建 Handler。处理程序按请求读取文件，从内容字节计算 ETag，并向已拥有当前版本的客户端回答 304。

设计决策：

  • 每个文件一个处理程序。 路由器没有通配符或前缀匹配，所以静态文件被枚举 — 每个资产一条路由。
  • ETag 来自内容，而不是时钟。 字节的 SHA-256 哈希仅在表示更改时更改，使其在重启和机器之间正确。
  • 整个文件在内存中。 适用于样式表、favicon 和文档页面。不适用于大文件（视频、下载）。
  • 缺失文件返回 404。 没有堆栈跟踪，没有目录列表。

基本用法

为单个文件创建处理程序。内容类型从文件扩展名推断：

import com.barezen.content.StaticContent;
import java.nio.file.Path;

Handler cssHandler = StaticContent.file(Path.of("public/styles.css"));
Handler jsHandler = StaticContent.file(Path.of("public/app.js"));
Handler imgHandler = StaticContent.file(Path.of("public/logo.png"));

注册路由

将每个静态文件注册为路由。因为路由器匹配精确路径，你为每个文件注册一条路由：

Router router = Router.builder()
    .route(HttpMethod.GET, "/styles.css",
        StaticContent.file(Path.of("public/styles.css")))
    .route(HttpMethod.GET, "/app.js",
        StaticContent.file(Path.of("public/app.js")))
    .route(HttpMethod.GET, "/logo.png",
        StaticContent.file(Path.of("public/logo.png")))
    .build();

HEAD 支持

如果表示的长度应该对使用 HEAD 询问的客户端可知，在 GET 和 HEAD 上注册相同的处理程序：

Handler cssHandler = StaticContent.file(Path.of("public/styles.css"));

Router router = Router.builder()
    .route(HttpMethod.GET, "/styles.css", cssHandler)
    .route(HttpMethod.HEAD, "/styles.css", cssHandler)
    .build();

自定义内容类型

通过显式提供内容类型来覆盖推断的内容类型：

// 将 .json 文件作为 application/manifest+json 提供
Handler manifest = StaticContent.file(
    Path.of("public/manifest.json"),
    "application/manifest+json");

// 使用自定义字符集提供 .html 文件
Handler page = StaticContent.file(
    Path.of("public/index.html"),
    "text/html; charset=utf-8");

ETag 和条件 GET

处理程序使用 SHA-256 从文件内容计算强 ETag（前 8 个字节，十六进制编码，带引号）。当客户端使用匹配的 ETag 发送 If-None-Match 时，处理程序返回 304 Not Modified，不带主体。

工作原理

  1. 客户端请求 GET /styles.css
  2. 服务器以 200 OK、主体和 ETag: "a1b2c3d4e5f60708" 响应
  3. 稍后，客户端使用 If-None-Match: "a1b2c3d4e5f60708" 请求 GET /styles.css
  4. 服务器读取文件，计算相同的 ETag，返回 304 Not Modified，不带主体

ETag 格式

ETag 是一个强标签：内容 SHA-256 哈希的前 8 个字节，十六进制编码，用双引号括起来。例如："a1b2c3d4e5f60708"。这提供 2^64 个值 — 对于一个部署提供的文件集无冲突。

If-None-Match 处理

处理程序支持 RFC 9110 定义的三种形状：

  • 通配符。 If-None-Match: * 匹配任何 ETag。
  • 逗号分隔列表。 If-None-Match: "abc", "def" 如果任何标签匹配则匹配。
  • 弱标签。 If-None-Match: W/"abc" 对于条件 GET 与 "abc" 相同处理。

错误处理

构建时文件未找到

如果文件在构建时不存在或不是常规文件，StaticContent.file() 抛出 IllegalArgumentException：

// 如果文件不存在则抛出 IllegalArgumentException
Handler handler = StaticContent.file(Path.of("public/missing.css"));

请求时文件消失

如果文件在构建时存在但在请求到达之前被删除，处理程序返回 404 Not Found — 与适配器用于其自身 404 的相同简单答案。不泄漏路径，不暴露堆栈跟踪。

空白内容类型

空白内容类型在构建时被拒绝。没有类型的字节流是浏览器猜测，框架拒绝成为那个浏览器。

动态资产注册

对于资产目录，在启动时枚举它们：

Path assetsDir = Path.of("public");
Router.Builder builder = Router.builder();

try (DirectoryStream<Path> stream = Files.newDirectoryStream(assetsDir)) {
    for (Path file : stream) {
        if (Files.isRegularFile(file)) {
            String name = file.getFileName().toString();
            String path = "/" + name;
            builder.route(HttpMethod.GET, path, StaticContent.file(file));
        }
    }
}
Router router = builder.build();

此模块不做的事情

  • 无目录列表。 目录会泄漏部署的布局。
  • 无流式传输。 整个文件被读入内存。对于大文件，编写自定义处理程序。
  • 无 Last-Modified 头部。 只使用 ETag。基于时钟的验证器会使输出不可测试。
  • 无缓存头部。 处理程序不设置 Cache-Control。如果需要缓存控制，添加中间件或包装处理程序。

最佳实践

  • 在启动时注册静态文件，而不是每请求 — 处理程序是无状态且可重用的。
  • 使用绝对路径或相对于工作目录的路径，而不是类路径资源。
  • 在生产中，考虑使用反向代理（Nginx、Caddy）提供静态文件 — 它更快且支持范围请求。
  • 在 GET 路由旁边注册 HEAD 路由，用于客户端可能在下载前检查大小的资产。

常见问题

"no regular file at /path/to/file"

文件在构建时不存在或是一个目录。检查路径并确保在构建路由器之前文件存在。

"the content type must not be blank"

你传递了一个空白字符串作为内容类型。提供有效的 MIME 类型或让框架从扩展名推断它。

存在文件的 404

文件在处理程序创建后被删除或移动。处理程序按请求重新读取文件，所以缺失的文件返回 404。检查文件路径和权限。
