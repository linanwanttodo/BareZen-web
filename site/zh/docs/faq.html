常见问题

关于 BareZen 设计、架构和使用模式的常见问题。

设计决策

为什么没有注解或反射？

BareZen 使用显式的、无反射的依赖注入（ADR-0014）。没有 @Inject、@Component 或 @Autowired 注解。应用在代码中声明它有什么，框架计算出创建顺序。这使得依赖在调用点可见、可搜索，并可用标准 IDE 工具重构。

为什么路由器是不可变的？

路由器在 build() 后是不可变的（ADR-0019）。没有 unregister()、replace() 或 reload()。这意味着请求线程不能与注册竞争 — 竞争不存在。如果你需要在运行时更改路由，构建一个新路由器并原子地交换引用。

为什么没有像 /assets/* 这样的通配符路由？

路由器使用精确段或 {name} 参数回答"这个请求是哪个处理程序的"。没有通配符、前缀匹配或多段捕获（ADR-0019 §5、§19）。对于静态文件，枚举它们 — 每个资产一条路由。这使路由器保持为一个简单的、单问题组件。

为什么请求主体在内存中？

Request.body() 返回 byte[]（ADR-0030）。流式主体需要契约说明谁关闭流、handler 未读取就返回时发生什么、handler 将其交给另一个线程时发生什么。这些问题都没有不依赖于服务器的答案。对于大文件上传，使用适配器的请求主体限制配置。

为什么 Response 中没有 Content-Length？

Content-Length 和 Transfer-Encoding 不是 handler 要写的（ADR-0027）。这些字段描述头部块后有多少字节 — 这是关于连接的事实，不是应用的答案。只有写入字节的适配器才能真正说明它们。适配器从主体字节派生 Content-Length。

为什么是两阶段启动？

启动分两个全局阶段运行（ADR-0003）：先初始化再启动。这保证了一个使工作可见的参与者（如绑定端口的 HTTP 服务器）只在每个前面的参与者完成设置后才这样做。按组件交错两个阶段无法表达这个不变量。

为什么 SecurityContext 不是 ThreadLocal？

线程不是请求。服务器线程可能处理多个请求，请求可能不在开始它的线程上完成。ThreadLocal 会将一个请求的身份泄漏到另一个。上下文是请求作用域的，通过中间件链传递。

架构

JdkHttpServerAdapter 和 BarezenServlet 有什么区别？

JdkHttpServerAdapterBarezenServlet
拥有端口是否 — 容器拥有
拥有线程是（虚拟或平台）否 — 容器拥有
生命周期HttpServerAdapter（start/stop）HttpServlet（init/destroy）

TLS通过配置内置容器管理

我可以在同一个应用中使用两个适配器吗？

可以，但它们会是不同端口上的独立服务器。通常你选择一个：嵌入式部署使用 JDK 适配器，容器部署使用 Servlet。

如何添加中间件？

BareZen 没有通用的中间件链。相反，使用这些模式：

  • RouteContributor — 用于从插件添加路由。
  • Handler 包装 — 包装处理程序以添加横切行为（日志、计时、CORS）。
  • SecurityMiddleware — 用于认证和授权。
// 示例：日志包装器
Handler logging(Handler inner) {
    return (req, params) -> {
        long start = System.nanoTime();
        try {
            return inner.handle(req, params);
        } finally {
            long elapsed = System.nanoTime() - start;
            System.out.println(req.method() + " " + req.path() + " " + elapsed + "ns");
        }
    };
}

如何处理 CORS？

包装你的处理程序以添加 CORS 头部：

Handler cors(Handler inner) {
    return (req, params) -> {
        if (req.method() == HttpMethod.OPTIONS) {
            return new Response(204, Headers.empty(), null);
        }
        Response response = inner.handle(req, params);
        // 向响应添加 CORS 头部
        return response; // 带额外头部
    };
}

如何覆盖配置？

配置层按最弱到最强排序：属性文件 < 环境变量 < 系统属性。要覆盖：

# 属性文件（最低优先级）
server.port=8080

# 环境变量（中等优先级）
export BAREZEN_HTTP_JDK_TLS_KEYSTOREPATH=/path/to/keystore.p12

# JVM 系统属性（最高优先级）
java -Dserver.port=9090 -jar app.jar

数据库

支持哪些数据库？

任何 JDBC 兼容的数据库。框架已使用 H2（内存）、PostgreSQL 和 MySQL 测试。Database 类与产品无关 — 它接收一个 DataSource，从不命名驱动。

如何使用连接池？

创建池化的 DataSource 并将其传递给 Database：

HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:postgresql://localhost/mydb");
config.setUsername("user");
config.setPassword("password");
DataSource ds = new HikariDataSource(config);
Database db = new Database(ds);

可以嵌套事务吗？

不可以。每个 transaction() 调用在新线程上打开新连接。不支持嵌套（ADR-0039）。如果你需要保存点，在事务回调内直接使用底层 JDBC 连接。

安全

401 和 403 有什么区别？

  • 401 Unauthorized — 客户端未认证。凭据错误或缺失。返回 AuthenticationResult.failure()。
  • 403 Forbidden — 客户端已认证但未授权。身份没有所需的权限。返回 Authorization.Decision.DENY。

如何实现 JWT 认证？

实现 Authentication 接口：

Authentication jwtAuth = (credential) -> {
    if (credential == null || !credential.scheme().equals("Bearer")) {
        return AuthenticationResult.anonymous();
    }
    try {
        Claims claims = Jwts.parser()
            .setSigningKey(secret)
            .parseClaimsJws(credential.value())
            .getBody();
        String username = claims.getSubject();
        return AuthenticationResult.authenticated(Principal.of(username));
    } catch (JwtException e) {
        return AuthenticationResult.failure("invalid token");
    }
};

会话是分布式的吗？

不是。SessionStore 仅在内存中。服务器重启会使所有会话无效。对于分布式部署，实现自己的由 Redis 或数据库支持的会话存储。

测试

为什么使用 TestServer 而不是模拟？

TestServer 在随机端口上启动真实的 HTTP 服务器。使用假服务器的集成测试只会证明假服务器有效。穿过套接字的字节是生产适配器产生的字节。

可以并行运行测试吗？

可以。每个 TestServer 使用随机端口（端口 0），所以并行测试类永远不会争夺固定数字。

部署

如何部署到生产？

两个选项：

  1. 嵌入式 — 打包为带 main() 方法的 JAR。使用来自 application.properties 配置的 JdkHttpServerAdapter。
  2. 容器 — 打包为 WAR。使用部署到 Tomcat、Jetty 或 Wildfly 的 BarezenServlet。

如何在生产中启用 HTTPS？

对于 JDK 适配器，在 application.properties 中配置密钥库：

barezen.http.jdk.tls.keystorePath=/path/to/keystore.p12
barezen.http.jdk.tls.keystorePassword=changeit

对于 Servlet 部署，在容器级别配置 TLS（Tomcat 的 server.xml、Jetty 的 etc/jetty-ssl.xml）。

如何处理优雅关闭？

LifecycleOrchestrator 默认注册 JVM 关闭钩子。它给进行中的请求 3 秒完成。对于容器部署，关闭关闭钩子：

LifecycleOrchestrator.builder()
    .registerShutdownHook(false)
    .build();

性能

BareZen 使用虚拟线程吗？

在 Java 21+ 上，是的 — 默认使用。JDK 适配器自动检测虚拟线程支持并使用它们。在 Java 17 上，它回退到平台线程。

请求主体限制是多少？

默认为 1 MB。通过 barezen.http.jdk.maxRequestBodyBytes（JDK 适配器）或 barezen.maxRequestBodyBytes 初始化参数（Servlet）配置它。超过限制的请求在处理程序运行前以 413 拒绝。

StaticContent 适合大文件吗？

不适合。StaticContent 将整个文件读入内存。它设计用于样式表、JavaScript、图像和小文档。对于大文件（视频、下载），编写一个流式传输响应的自定义处理程序。

如果我需要 BareZen 没有的功能怎么办？

BareZen 设计为最小。如果你需要内置没有的功能：

  • 为横切关注点（日志、CORS、速率限制）编写处理程序包装器。
  • 为插件式路由添加编写 RouteContributor。
  • 与 BareZen 一起使用标准 Java 库（Jackson 用于 JSON、HikariCP 用于池化）。

框架提供契约（Request、Response、Handler、Router），让你填充其余部分。
