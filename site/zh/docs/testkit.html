TestKit

barezen-testkit 提供 TestServer、TestHttpClient、Assertions 和 TestDatabase — 用于集成测试整个栈的工具。

模块概览

barezen-testkit 模块提供用于集成测试 BareZen 应用的工具。与模拟一切的单元测试不同，TestKit 在随机端口上启动真实的 HTTP 服务器，让你向它发送真实的 HTTP 请求。

关键类型：

类型角色
TestServer随机回环端口上的真实 HTTP 服务器
TestHttpClient与 TestServer 通信的薄型 HTTP 客户端
TestResponse来自 TestHttpClient 的响应：状态码、头部、主体
Assertions用于响应、计数和安全身份的流式断言
TestDatabase用于测试的内存 H2 数据库
PrincipalFixture用于安全身份断言的测试夹具

TestServer

TestServer 在随机回环端口上包装 JdkHttpServerAdapter。它将真实的适配器绑定到 127.0.0.1 的端口 0，所以操作系统返回一个未使用的端口 — 并行测试类永远不会争夺固定数字。

基本用法

import com.barezen.testkit.TestServer;
import com.barezen.testkit.Assertions;

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", (req, params) ->
        new Response(200, Headers.of("Content-Type", "text/plain"), "OK".getBytes()))
    .build();

try (TestServer server = TestServer.start(router)) {
    TestResponse response = server.client().get("/health");
    Assertions.assertThat(response).statusIs(200).bodyIs("OK");
}  // 服务器自动停止并释放端口

API 方法

方法描述
start(Router)在随机端口上启动服务器。返回已启动的服务器。
port()返回绑定的端口（启动后始终为正数）。
baseUri()返回基本 URI，例如 http://127.0.0.1:45678。
client()返回连接到此服务器的 TestHttpClient。
isRunning()如果服务器仍在服务，返回 true。
close()停止服务器。幂等 — 安全地调用两次。

Try-with-resources

始终使用 try-with-resources 以确保端口被释放：

try (TestServer server = TestServer.start(router)) {
    // 运行测试
}  // 即使测试失败端口也会被释放

TestHttpClient

TestHttpClient 是一个与 TestServer 通信的薄型 HTTP 客户端。它针对服务器的基本 URI 解析路径并返回 TestResponse 对象。

HTTP 动词方法

框架路由的每个动词都有一个直接方法：

TestHttpClient client = server.client();

// GET
TestResponse get = client.get("/users");

// HEAD
TestResponse head = client.head("/users");

// 带主体的 POST
TestResponse post = client.post("/users", "{\"name\":\"Alice\"}");

// 带主体的 PUT
TestResponse put = client.put("/users/1", "{\"name\":\"Bob\"}");

// 带主体的 PATCH
TestResponse patch = client.patch("/users/1", "{\"name\":\"Carol\"}");

// DELETE
TestResponse delete = client.delete("/users/1");

// OPTIONS
TestResponse options = client.options("/users");

自定义请求

对于带有自定义头部或快捷方式未覆盖的任何方法的请求：

TestResponse response = client.request(HttpMethod.GET, "/users")
    .header("Accept", "application/json")
    .header("Authorization", "Bearer token123")
    .send();

请求构建器

方法描述
header(String name, String value)添加请求头部。可链接。
body(String body)将请求主体设置为 UTF-8 文本。
send()发送请求并返回响应。

超时

请求有 10 秒超时。如果服务器在 10 秒内没有响应，会抛出 TestRequestFailedException。

TestResponse

TestResponse 携带来自服务器的状态码、头部和主体：

方法描述
status()返回 HTTP 状态码（例如，200、404）。
header(String name)返回头部的第一个值作为 Optional<String>。不区分大小写的名称匹配。
body()将响应主体作为 UTF-8 字符串返回。
bodyBytes()将响应主体作为原始字节返回。

Assertions

Assertions 为 BareZen 集成测试提供流式断言。每个失败都抛出 AssertionError，显示期望的和实际返回的内容。

响应断言

Assertions.assertThat(response)
    .statusIs(200)
    .headerIs("Content-Type", "application/json")
    .bodyIs("{\"message\":\"ok\"}")
    .bodyContains("\"id\":1");

断言方法

方法描述
statusIs(int)断言状态码。
headerIs(String, String)断言头部的精确值。
headerExists(String)断言头部存在，无论其值如何。
bodyIs(String)断言主体等于期望的字符串（UTF-8）。
bodyContains(String)断言主体包含期望的子字符串。
jsonStringIs(String path, String expected)断言 JSON 路径的字符串值。点分隔路径。
jsonNumberIs(String path, Number expected)断言 JSON 路径的数值。

计数断言

断言处理程序的调用计数：

CountingHandler handler = new CountingHandler((req, params) ->
    new Response(200, Headers.empty(), null));

// ... 调用处理程序 ...

Assertions.assertThat(handler.count()).isEqualTo(1);

身份断言

断言夹具记录的安全身份：

PrincipalFixture fixture = new PrincipalFixture();
// ... 将夹具连接到安全中间件 ...

Assertions.assertThat(fixture.seen()).hasName("alice");

TestDatabase

TestDatabase 为测试提供内存 H2 数据库：

try (TestDatabase testDb = TestDatabase.create()) {
    Database db = testDb.database();

    // 运行迁移
    Migrator migrator = new Migrator(db);
    migrator.migrate(List.of(createUsersTable));

    // 在测试中使用数据库
    db.executeUpdate("INSERT INTO users (name, email) VALUES (?, ?)",
        "Alice", "alice@example.com");

    List<User> users = db.query(
        "SELECT id, name, email FROM users",
        userMapper);
}

API 方法

方法描述
create()创建新的内存 H2 数据库。在 try-with-resources 结束时自动关闭。
database()返回用于查询和更新的 Database 实例。
dataSource()如果你需要它，返回底层 DataSource。
close()关闭数据库连接。幂等。

完整测试示例

import com.barezen.testkit.*;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

class UserApiTest {

    @Test
    void createUser() {
        // 1. 设置内存数据库
        try (TestDatabase testDb = TestDatabase.create()) {
            Database db = testDb.database();

            // 2. 运行迁移
            new Migrator(db).migrate(List.of(createUsersTable));

            // 3. 构建应用组件
            UserRepository repo = new UserRepository(db);
            Handler createUser = (req, params) -> {
                Map<String, String> body = parseJson(req.body());
                User user = repo.create(
                    body.get("name"),
                    body.get("email"),
                    "hashed-password");
                return new Response(201,
                    Headers.of("Content-Type", "application/json"),
                    ("{\"id\":" + user.id() + "}").getBytes());
            };

            // 4. 构建路由器
            Router router = Router.builder()
                .route(HttpMethod.POST, "/users", createUser)
                .build();

            // 5. 启动测试服务器
            try (TestServer server = TestServer.start(router)) {
                // 6. 发送请求
                TestResponse response = server.client()
                    .post("/users", "{\"name\":\"Alice\",\"email\":\"alice@example.com\"}");

                // 7. 断言
                Assertions.assertThat(response)
                    .statusIs(201)
                    .headerIs("Content-Type", "application/json")
                    .bodyContains("\"id\":");
            }
        }
    }
}

最佳实践

  • 对 TestServer 和 TestDatabase 使用 try-with-resources 以确保清理。
  • 对需要数据库的测试使用 TestDatabase — 它每个测试是隔离的。
  • 使用 Assertions.assertThat() 获取显示期望与实际值的可读测试失败。
  • 并行运行测试 — 每个 TestServer 使用随机端口，所以它们不会冲突。
  • 对于安全测试，在测试中使用 Authentication.bearer() 进行简单的基于令牌的认证。

常见问题

"Connection refused"

测试服务器未启动或已关闭。确保在发送请求之前调用 TestServer.start()，并且服务器在测试完成之前未关闭。

"TestRequestFailedException"

请求无法完成 — 连接被拒绝、超时或中断。检查服务器是否正在运行且路径正确。

"expected status 200 but got 404"

路由未注册或路径不匹配。检查路由器配置和请求路径。
