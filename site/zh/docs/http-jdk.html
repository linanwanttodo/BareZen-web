JDK HTTP 适配器

barezen-http-jdk 在 JDK 内置的 com.sun.net.httpserver 上提供 HttpServerAdapter，支持虚拟线程和 TLS/HTTPS。

模块概览

barezen-http-jdk 模块将 JDK 自己的 HTTP 服务器（com.sun.net.httpserver）适配到 BareZen Web 契约。这是框架中唯一命名该包的模块 — 其他一切保持与服务器无关（ADR-0021）。

主要功能：

  • Java 21+ 上的虚拟线程。 自动检测并在可用时使用虚拟线程，否则使用平台线程。
  • TLS/HTTPS 支持。 可通过密钥库路径和密码配置。
  • 请求主体限制。 防止无界主体读取导致的拒绝服务。
  • 错误处理。 为路由和协议错误生成 404、405、400、413 和 500 响应。

构造函数

有三个公共构造函数，每个都有不同的配置选项：

简单构造函数（自动配置）

InetSocketAddress address = new InetSocketAddress("0.0.0.0", 8080);
JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(address, router);

此构造函数：

  • 使用 ThreadPolicy.AUTO 创建自己的 ThreadProvider（Java 21+ 上使用虚拟线程，否则使用平台线程）。
  • 使用配置键默认值的默认请求主体限制。
  • 提供明文 HTTP（无 TLS）。
  • 拥有线程提供者在 stop() 时关闭它。

带共享 ThreadProvider 的构造函数

ThreadProvider threads = ThreadProviders.create(
    ThreadPolicy.VIRTUAL, RuntimeCapabilities.detect());

JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, threads);

此构造函数借用线程提供者 — 它从中创建一个执行器但从不关闭任何一个。调用者拥有提供者，应在 adapter.stop() 后关闭它。

带 Configuration 的构造函数

Configuration config = Configuration.standard(
    Path.of("application.properties"));

JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, config);

此构造函数读取以下配置键：

键类型默认值描述
barezen.http.jdk.maxRequestBodyBytesLong1 MB最大请求主体大小（字节）。超过此限制的请求以 413 拒绝。
barezen.http.jdk.tls.keystorePathString无（明文）密钥库文件路径（JKS 或 PKCS12）。不存在表示明文 HTTP。
barezen.http.jdk.tls.keystorePasswordString如果设置了 keystorePath 则必需打开密钥库的密码。当 keystorePath 存在时必需。

生命周期

适配器遵循严格的生命周期：NEW → RUNNING → STOPPED，没有回退路径。第二次 start() 会抛出异常，start → stop → start 也会。重启需要构建新的适配器。

启动

adapter.start();
// 服务器现在在配置的地址上监听
int port = adapter.port().getAsInt();  // 实际绑定的端口

start() 绑定端口并开始接受连接。如果绑定失败（例如，端口已在使用），它会抛出 UncheckedIOException 并将适配器留在 STOPPED 状态。

停止

adapter.stop();  // 幂等，永不抛出异常

stop() 给进行中的交换 3 秒完成，然后释放资源。它是幂等的 — 对从未启动的适配器调用它是合法的，什么都不做。

查询方法

boolean running = adapter.isRunning();  // start() 和 stop() 之间为 true
OptionalInt port = adapter.port();      // 实际绑定的端口（未运行时为空）

TLS / HTTPS 配置

要启用 HTTPS，在 application.properties 中配置密钥库路径和密码：

# application.properties
barezen.http.jdk.tls.keystorePath=/path/to/keystore.p12
barezen.http.jdk.tls.keystorePassword=changeit

或通过环境变量设置：

export BAREZEN_HTTP_JDK_TLS_KEYSTOREPATH=/path/to/keystore.p12
export BAREZEN_HTTP_JDK_TLS_KEYSTOREPASSWORD=changeit

创建密钥库

使用 JDK 的 keytool 创建密钥库：

# 创建带有自签名证书的 PKCS12 密钥库
keytool -genkeypair \
  -alias server \
  -keyalg RSA \
  -keysize 2048 \
  -storetype PKCS12 \
  -keystore keystore.p12 \
  -validity 365 \
  -dname "CN=localhost, OU=Dev, O=MyOrg, L=City, ST=State, C=US" \
  -storepass changeit \
  -keypass changeit

TLS 协议

适配器使用 TLSv1.2 作为上限，优先 TLSv1.3，这是 JDK 的默认排序。不配置协议列表，不选择密码套件，不请求客户端证书（无 mTLS）。

错误处理

  • 如果设置了 keystorePath 但 keystorePassword 不存在，构建以 ConfigurationException 失败。
  • 如果无法打开密钥库文件，构建以 ConfigurationException 失败，命名路径和 JDK 异常。
  • 密码永远不会在错误消息或日志中回显。

请求主体限制

适配器强制执行最大请求主体大小以防止拒绝服务攻击。默认为 1 MB（1,048,576 字节）。超过此限制的请求在处理程序运行前以 413 Payload Too Large 拒绝。

在 application.properties 中配置限制：

# application.properties
barezen.http.jdk.maxRequestBodyBytes=5242880  # 5 MB

线程模型

默认情况下，适配器使用 ThreadPolicy.AUTO 创建自己的 ThreadProvider：

  • Java 21+ — 每个请求在虚拟线程上运行。这以低内存开销提供高并发。
  • Java 17 — 每个请求来自缓存池的平台线程上运行。

要强制特定的线程模型，使用带共享 ThreadProvider 的构造函数：

ThreadProvider threads = ThreadProviders.create(
    ThreadPolicy.VIRTUAL, RuntimeCapabilities.detect());

JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, threads);

错误响应

适配器处理以下错误情况：

状态码何时
400 Bad Request格式错误的请求行或无效的 HTTP 方法。
404 Not Found没有路由匹配请求方法和路径。
405 Method Not Allowed路径存在路由但不是请求的方法。Allow 头部列出允许的方法。
413 Payload Too Large请求主体超过配置的限制。
500 Internal Server Error处理程序抛出异常。错误主体不包含详细信息 — 只有服务器日志有。

与 LifecycleOrchestrator 一起使用

Configuration config = Configuration.standard(
    Path.of("application.properties"));

InetSocketAddress address = new InetSocketAddress("0.0.0.0", 8080);
JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(
    address, router, config);

LifecycleOrchestrator orchestrator = LifecycleOrchestrator.builder()
    .register("http", adapter)
    .build();

try {
    orchestrator.start();
    // 服务器正在运行
} finally {
    orchestrator.stop();
}

使用临时端口

对于测试或当你希望操作系统选择空闲端口时，使用端口 0：

InetSocketAddress address = new InetSocketAddress("127.0.0.1", 0);
JdkHttpServerAdapter adapter = new JdkHttpServerAdapter(address, router);
adapter.start();

int actualPort = adapter.port().getAsInt();
System.out.println("服务器在端口 " + actualPort + " 上监听");

最佳实践

  • 在生产中使用 Configuration 构造函数从配置文件读取主体限制和 TLS 设置。
  • 在测试中使用端口 0 以避免并行测试运行之间的端口冲突。
  • 将适配器注册为编排器中的最后一个参与者，以便在服务器绑定之前完全设置路由。
  • 对于 HTTPS，使用 PKCS12 密钥库（Java 9 以来的 JDK 默认值）。
  • 永远不要在日志或错误消息中暴露密钥库密码 — 框架强制执行此操作。

常见问题

"Address already in use"

端口已被另一个进程绑定。更改端口或停止其他进程。使用 lsof -i :8080 或 netstat -tlnp | grep 8080 查找进程。

"keystorePath names a keystore but keystorePassword supplies no password"

你设置了密钥库路径但忘记了密码。TLS 需要两个键。在配置中设置 barezen.http.jdk.tls.keystorePassword。

"cannot start the JDK HTTP server on ..."

绑定失败。检查主机地址是否正确（使用 0.0.0.0 表示所有接口，127.0.0.1 表示仅本地主机）以及端口是否可用。

"this adapter is STOPPED and cannot be started again"

适配器已停止。构建新的 JdkHttpServerAdapter 实例以重启。适配器不支持重启 — 一个实例，一个生命周期。
