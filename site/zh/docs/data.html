数据模块

barezen-data 提供 Database、Transaction、RowMapper 和 Migration — 一个带事务和模式迁移的最小 JDBC 层。

模块概览

barezen-data 模块提供一个基于 JDBC 的薄型、与产品无关的数据层。它接收一个 DataSource 并提供查询、更新、事务和模式迁移 — 而不知道它与哪个数据库通信。

关键类型：

类型角色
Database入口点：查询、更新、事务
Transaction事务作用域访问，用于多语句工作单元
RowMapper将 ResultSet 行映射到域对象
Migration一个模式或数据更改，由版本号标识
Migrator按版本顺序应用待处理的迁移
DataAccessException包装 SQLException 的运行时异常

Database

Database 是数据层的入口点。它接收一个 DataSource，从不命名驱动、URL、用户或密码 — 应用的组装代码创建数据源并将其传递。

创建 Database

// 使用 H2 内存数据库（用于测试）
JdbcDataSource dataSource = new JdbcDataSource();
dataSource.setURL("jdbc:h2:mem:test;DB_CLOSE_DELAY=-1");
Database db = new Database(dataSource);

// 使用连接池（用于生产）
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:postgresql://localhost/mydb");
config.setUsername("user");
config.setPassword("password");
DataSource dataSource = new HikariDataSource(config);
Database db = new Database(dataSource);

两种访问风格

它们之间的区别是整个事务故事（ADR-0039）：

自动提交风格（单语句）

query() 和 executeUpdate() 在借用用于调用的连接上运行，使用池的自动提交默认值。对这些是自身完整单元的语句使用这些：

// 单个查询
List<User> users = db.query(
    "SELECT id, name, email FROM users WHERE active = ?",
    (rs, rowNum) -> new User(
        rs.getLong("id"),
        rs.getString("name"),
        rs.getString("email")),
    true);

// 单个更新
int rows = db.executeUpdate(
    "UPDATE users SET name = ? WHERE id = ?",
    "Alice", 1L);

事务风格（多语句工作单元）

transaction() 打开一个连接，将其放在事务作用域中，运行回调，在回调正常返回时提交。跨越多个语句的工作单元使用此路径：

db.transaction((tx) -> {
    tx.executeUpdate("INSERT INTO users (name, email) VALUES (?, ?)",
        "Alice", "alice@example.com");
    long userId = tx.queryForLong(
        "SELECT last_insert_id()");
    tx.executeUpdate("INSERT INTO profiles (user_id, bio) VALUES (?, ?)",
        userId, "Hello!");
    return userId;
});  // 成功时自动提交，失败时回滚

事务保证

场景结果
回调正常返回commit() — 更改是持久的
回调抛出 SQLExceptionrollback() — 失败被转换为 DataAccessException
回调抛出 RuntimeExceptionrollback() — 失败原样传播
回调返回但提交失败先回滚，然后抛出 DataAccessException

在所有情况下，连接在 transaction() 返回之前关闭。

Transaction API

在事务回调内部，你接收一个与 Database 具有相同方法的 Transaction：

方法描述
query(sql, mapper, params)执行查询并映射行
executeUpdate(sql, params)执行插入/更新/删除，返回受影响的行数
queryForLong(sql, params)执行返回单个 long 值的查询

连接生命周期

在任何公共方法返回之前，每条路径上的连接都被关闭 — 正常返回、转换的失败、应用异常或清理失败。PreparedStatement 和 ResultSet 在内部管理，从不交给调用者。

异常转换

离开此模块的每个 SQLException 都作为 DataAccessException 重新抛出，命名 SQL 或操作，并将驱动异常保留为原因。回调抛出的运行时异常不被转换 — 它是应用自己的失败类型。

RowMapper

RowMapper 是一个函数式接口，将 ResultSet 行映射到域对象：

@FunctionalInterface
public interface RowMapper<T> {
    T map(ResultSet rs, int rowNum) throws SQLException;
}

使用示例

RowMapper<User> userMapper = (rs, rowNum) -> new User(
    rs.getLong("id"),
    rs.getString("name"),
    rs.getString("email"),
    rs.getTimestamp("created_at") != null
        ? rs.getTimestamp("created_at").toLocalDateTime()
        : null);

List<User> users = db.query(
    "SELECT id, name, email, created_at FROM users",
    userMapper);

Schema 迁移

迁移是按顺序应用的带版本号的模式或数据更改。Migrator 在历史表中跟踪哪些版本已应用，并只运行待处理的版本。

Migration 接口

public interface Migration {
    long version();       // 正数、唯一、严格递增
    String description(); // 存储在历史表中的人类标签
    void apply(Connection connection) throws SQLException;
}

编写迁移

Migration createUsersTable = new Migration() {
    @Override
    public long version() {
        return 1L;
    }

    @Override
    public String description() {
        return "Create users table";
    }

    @Override
    public void apply(Connection conn) throws SQLException {
        try (Statement stmt = conn.createStatement()) {
            stmt.execute("""
                CREATE TABLE users (
                    id BIGINT PRIMARY KEY AUTO_INCREMENT,
                    name VARCHAR(255) NOT NULL,
                    email VARCHAR(255) NOT NULL UNIQUE,
                    password_hash VARCHAR(500) NOT NULL,
                    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
                )
            """);
        }
    }
};

应用迁移

Migrator migrator = new Migrator(db);
migrator.migrate(List.of(
    createUsersTable,
    createProfilesTable,
    addEmailVerifiedColumn
));

迁移保证

  • 记录的版本永远不会再次运行。
  • 迁移按版本顺序运行。
  • 每个迁移在其自己的事务中运行。
  • 如果迁移失败，其版本不会被记录，也没有后面的迁移运行。
  • 失败的迁移可能会留下模式 — 以幂等方式编写 DDL（IF NOT EXISTS），以便重试的迁移完成。

历史表

迁移器自动创建 applied_migrations 表：

CREATE TABLE applied_migrations (
    version BIGINT PRIMARY KEY,
    description VARCHAR(255) NOT NULL,
    applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)

DataAccessException

一个包装 SQLException 的运行时异常。它携带 SQL 或操作名称，原始驱动异常作为原因：

try {
    db.query("SELECT * FROM nonexistent", mapper);
} catch (DataAccessException e) {
    // e.getMessage() — "query failed: SELECT * FROM nonexistent"
    // e.getCause() — 驱动程序的原始 SQLException
    log.error("数据库错误: {}", e.getMessage(), e);
}

完整示例：用户仓库

public class UserRepository {

    private final Database db;

    public UserRepository(Database db) {
        this.db = db;
    }

    public Optional<User> findById(long id) {
        List<User> users = db.query(
            "SELECT id, name, email, password_hash, created_at FROM users WHERE id = ?",
            (rs, rowNum) -> new User(
                rs.getLong("id"),
                rs.getString("name"),
                rs.getString("email"),
                rs.getString("password_hash"),
                rs.getTimestamp("created_at").toLocalDateTime()),
            id);
        return users.stream().findFirst();
    }

    public User create(String name, String email, String passwordHash) {
        long id = db.transaction((tx) -> {
            tx.executeUpdate(
                "INSERT INTO users (name, email, password_hash) VALUES (?, ?, ?)",
                name, email, passwordHash);
            return tx.queryForLong("SELECT last_insert_id()");
        });
        return findById(id).orElseThrow();
    }

    public void updateEmail(long id, String newEmail) {
        db.executeUpdate(
            "UPDATE users SET email = ? WHERE id = ?",
            newEmail, id);
    }
}

最佳实践

数据库访问

  • 对单语句操作使用 query() 和 executeUpdate()。
  • 对多语句工作单元使用 transaction()。
  • 永远不要嵌套 transaction() 调用 — 每个都打开一个新连接。
  • 使用参数化查询（?） — 永远不要将 SQL 与用户输入连接。

迁移

  • 以幂等方式编写 DDL：使用 IF NOT EXISTS 和 IF EXISTS。
  • 分配严格递增且永不重用的版本号。
  • 保持描述具有描述性 — 它们出现在操作员的历史表中。
  • 针对你部署到的实际数据库产品测试迁移。

连接池

  • 在生产中使用连接池（HikariCP、Tomcat JDBC）。
  • 在测试中使用未池化的 JdbcDataSource（H2）。
  • 框架从不询问它得到了什么类型的 DataSource — 它的行为相同。

常见问题

"query failed: ..." 带有 DataAccessException

SQL 查询失败。检查原因（e.getCause()）以获取驱动程序的 SQLException 的详细信息。常见原因：语法错误、缺少表或类型不匹配。

"could not acquire a connection from the data source"

DataSource 无法产生连接。检查数据库是否正在运行、URL 是否正确以及凭据是否有效。

"transaction failed and was rolled back"

事务回调内的语句失败。事务已回滚，没有提交任何更改。检查回调的 SQL 和参数。

"Migration version X already applied"

已再次提交已记录版本的迁移。版本号必须唯一且严格递增。
