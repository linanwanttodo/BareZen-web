安全模块

barezen-security 提供认证、授权、会话管理和密码哈希 — 全部可插拔且请求作用域。

模块概览

barezen-security 模块为 BareZen 应用提供完整的安全层。它围绕三个核心关注点组织：

关注点类型描述
认证Authentication, AuthenticationResult, Credential验证客户端声称的身份
授权Authorization, Permission, Principal决定已认证身份可以做什么
会话SessionStore, SessionToken带令牌的状态会话管理
密码PasswordHasherPBKDF2-HMAC-SHA256 密码哈希
中间件SecurityMiddleware, SecurityContext, SecuredHandler将认证和授权连接到请求管道

认证

认证回答"这个客户端是谁？"。Authentication 接口是一个带有一个方法的函数式接口：

@FunctionalInterface
public interface Authentication {
    AuthenticationResult authenticate(Credential credential);
}

AuthenticationResult — 三种状态

HTTP 安全有三个答案，结果是一个密封层次结构，使所有三个都明确：

状态工厂HTTP 响应含义
AuthenticatedAuthenticationResult.authenticated(principal)通过客户端证明了身份
FailureAuthenticationResult.failure("reason")401 Unauthorized客户端提供的凭据未验证
AnonymousAuthenticationResult.anonymous()取决于授权客户端根本没有提供凭据

Failure 和 Anonymous 之间的区别至关重要：错误的凭据是一个未能证明任何内容的请求（401），而没有凭据是一个可能被允许也可能不被允许的有效请求（取决于授权是 401 还是 403）。

Credential

Credential 是一个带有两个字段的记录：scheme（例如 "Bearer"、"Basic"）和 value（令牌或编码凭据）。中间件从 Authorization 头部提取凭据并将其传递给认证实现。

内置认证实现

匿名认证

不信任任何东西 — 每个请求都是匿名的。在未配置认证时用作默认值：

Authentication auth = Authentication.anonymous();

Bearer 令牌认证

匹配固定的方案和值。适用于测试和简单的 API 密钥设置：

Principal admin = Principal.of("admin");
Authentication auth = Authentication.bearer("Bearer", "secret-token-123", admin);

自定义认证

实现 Authentication 以针对数据库、外部服务或令牌颁发者验证凭据：

Authentication auth = (credential) -> {
    if (credential == null) {
        return AuthenticationResult.anonymous();
    }
    // 通过令牌查找用户
    Optional<User> user = userRepository.findByToken(credential.value());
    if (user.isPresent()) {
        return AuthenticationResult.authenticated(
            Principal.of(user.get().username()));
    }
    return AuthenticationResult.failure("invalid token");
};

授权

授权回答"这个身份是否被允许这样做？"。Authorization 接口是一个函数式接口：

@FunctionalInterface
public interface Authorization {
    Decision authorize(Principal principal, Permission required);
}

Decision

两种状态：ALLOW（通过）或 DENY（403 Forbidden）。默认是拒绝 — 没有明确授予的身份没有权限。

内置授权实现

允许所有

每个已认证的身份都有每个权限。适用于测试：

Authorization authz = Authorization.allowAll();

拒绝所有

没有已认证的身份有任何权限。在未配置授权时用作默认值：

Authorization authz = Authorization.denyAll();

基于表的授权

固定表将主体映射到其权限：

Permission READ = Permission.of("read:users");
Permission WRITE = Permission.of("write:users");

Principal alice = Principal.of("alice");
Principal bob = Principal.of("bob");

Authorization authz = Authorization.of(Map.of(
    alice, Set.of(READ, WRITE),
    bob, Set.of(READ)));

// alice 可以读写
// bob 只能读
// 其他任何人被拒绝

Permission

Permission 是一个不可变的字符串标识符。使用点分隔的名称表示层次结构：

Permission.READ_USERS = Permission.of("read:users");
Permission.WRITE_USERS = Permission.of("write:users");
Permission.DELETE_USERS = Permission.of("delete:users");

SecurityContext

SecurityContext 是一个请求作用域的值，携带认证结果。它不是线程局部变量、不是会话、不是缓存：

public record SecurityContext(AuthenticationResult authentication) {
    public Optional<Principal> principal();
    public boolean isAuthenticated();
}

上下文是不可变的，因为请求的安全答案一旦确定。Handler 不能改变它正在回答的请求的身份。

SecuredHandler

使用 SecuredHandler 用安全要求包装处理程序：

Handler inner = (req, params) -> {
    // 只有认证和授权通过时此代码才运行
    return new Response(200, ...);
};

// 需要认证（任何已认证用户）
Handler secured = SecuredHandler.authenticated(inner);

// 需要特定权限
Handler secured = SecuredHandler.require(inner, Permission.of("write:users"));

SecurityMiddleware

中间件将认证和授权连接到请求管道。它实现 RouteContributor 和 LifecycleParticipant：

SecurityMiddleware middleware = SecurityMiddleware.create(
    Authentication.bearer("Bearer", "secret", Principal.of("admin")),
    Authorization.allowAll());

Router router = Router.builder()
    .route(HttpMethod.GET, "/health", healthHandler)
    .contributing(List.of(middleware))
    .build();

中间件做什么

  1. 从请求中提取 Authorization 头部
  2. 创建 Credential（如果不存在则为 null）
  3. 调用 Authentication.authenticate(credential)
  4. 如果为 Failure，返回 401 Unauthorized
  5. 如果为 Authenticated 且处理程序需要权限，调用 Authorization.authorize()
  6. 如果授权拒绝，返回 403 Forbidden
  7. 创建 SecurityContext 并将其传递给处理程序

会话管理

SessionStore 提供内存会话管理。会话以随机令牌为键，在配置的持续时间后过期。

创建会话

SessionStore store = SessionStore.standard();

// 成功登录后：
SessionStore.Session session = store.create(
    Principal.of("alice"),
    Duration.ofHours(24));

// 将令牌返回给客户端（例如，在 Set-Cookie 头部中）
String token = session.token().value();

查找会话

Optional<SessionStore.Session> session = store.lookup(token);
if (session.isPresent()) {
    Principal principal = session.get().principal();
    // 会话有效且未过期
} else {
    // 令牌未知或已过期
}

使会话无效（注销）

boolean removed = store.invalidate(token);

轮换会话

轮换为同一主体创建新令牌，使旧令牌无效。在密码更改或权限提升后使用：

Optional<SessionStore.Session> newSession = store.rotate(oldToken, Duration.ofHours(24));

会话令牌

SessionToken 是一个 32 字节的随机值，编码为 URL 安全的 Base64。它携带过期时间，可以检查是否过期：

SessionToken token = session.token();
boolean expired = token.isExpired(Clock.systemUTC().instant());

密码哈希

PasswordHasher 使用 PBKDF2 和 HMAC-SHA-256。默认迭代次数为 600,000（OWASP 2023 推荐）。

哈希密码

PasswordHasher hasher = PasswordHasher.standard();

// 哈希密码以存储
String hash = hasher.hash("user-password");
// 格式：PBKDF2WithHmacSHA256$600000$<base64-salt>$<base64-derived-key>

// 将哈希存储在数据库中
userRepository.save(username, hash);

验证密码

// 检索存储的哈希
String storedHash = userRepository.findHash(username);

// 验证
if (hasher.verify("user-password", storedHash)) {
    // 密码匹配
} else {
    // 密码不匹配
}

编码格式

哈希是自描述的：algorithm$iterations$salt$derivedKey，全部 Base64 编码。这意味着：

  • 迭代次数存储在哈希中，因此你可以更改默认值而无效旧哈希。
  • 格式错误的哈希被拒绝为验证失败，而不是异常。
  • 原始密码永远不会存储、永远不会记录、永远不会返回。

测试友好的哈希

对于测试，使用较低的迭代次数和固定的随机源：

PasswordHasher testHasher = PasswordHasher.of(
    1000, new SecureRandom(42));

完整示例：登录流程

// 1. 设置密码哈希
PasswordHasher hasher = PasswordHasher.standard();

// 2. 设置会话存储
SessionStore sessionStore = SessionStore.standard();
Duration sessionDuration = Duration.ofHours(24);

// 3. 认证：从请求主体验证用户名/密码
Authentication auth = (credential) -> {
    if (credential == null) {
        return AuthenticationResult.anonymous();
    }
    // 从 Basic 认证或自定义主体解析用户名:密码
    String[] parts = decodeCredential(credential);
    String username = parts[0];
    String password = parts[1];

    Optional<String> storedHash = userRepository.findHash(username);
    if (storedHash.isPresent() && hasher.verify(password, storedHash.get())) {
        return AuthenticationResult.authenticated(Principal.of(username));
    }
    return AuthenticationResult.failure("invalid credentials");
};

// 4. 授权
Authorization authz = Authorization.of(Map.of(
    Principal.of("admin"), Set.of(
        Permission.of("read:users"),
        Permission.of("write:users"))));

// 5. 创建中间件
SecurityMiddleware middleware = SecurityMiddleware.create(auth, authz);

// 6. 登录处理程序
Handler login = (req, params) -> {
    // 从请求主体解析用户名和密码
    Map<String, String> body = parseJson(req.body());
    String username = body.get("username");
    String password = body.get("password");

    Optional<String> storedHash = userRepository.findHash(username);
    if (storedHash.isPresent() && hasher.verify(password, storedHash.get())) {
        SessionStore.Session session = sessionStore.create(
            Principal.of(username), sessionDuration);
        return new Response(200,
            Headers.of("Content-Type", "application/json")
                .with("Set-Cookie", "session=" + session.token().value()),
            "{\"status\":\"ok\"}".getBytes());
    }
    return new Response(401,
        Headers.of("Content-Type", "application/json"),
        "{\"error\":\"invalid credentials\"}".getBytes());
};

// 7. 注册路由
Router router = Router.builder()
    .route(HttpMethod.POST, "/login", login)
    .route(HttpMethod.DELETE, "/logout", logoutHandler)
    .contributing(List.of(middleware))
    .build();

最佳实践

认证

  • 始终返回三种状态之一 — 永远不要为预期失败从 authenticate() 抛出异常。
  • 对错误凭据使用 Failure，对缺失凭据使用 Anonymous。
  • 永远不要记录原始凭据值。

授权

  • 默认拒绝 — 未配置的设置不应静默允许。
  • 使用描述性权限名称：read:users、write:users、delete:users。
  • 匿名请求在调用授权之前被中间件拒绝。

会话

  • 对敏感应用使用短会话持续时间（1-24 小时）。
  • 在密码更改或权限提升后轮换会话。
  • 会话仅在内存中 — 服务器重启会使所有会话无效。
  • 对于分布式部署，使用外部会话存储（Redis、数据库）。

密码

  • 始终使用 PasswordHasher — 永远不要存储明文密码。
  • 在生产中使用默认迭代次数（600,000）。
  • 仅在测试中使用较低的迭代次数（1,000）。
  • 哈希格式是自描述的 — 你可以随时间更改迭代次数。

常见问题

"401 vs 403 混淆"

401 表示"你未认证" — 客户端应提供凭据。403 表示"你已认证但未授权" — 客户端的身份没有所需的权限。对 401 使用 Failure，对 403 使用 DENY。

"会话过期但令牌仍有效"

SessionStore.lookup() 自动检查过期。如果找到令牌但已过期，它会被移除并返回 Optional.empty()。不需要手动过期检查。

"密码哈希验证很慢"

这是有意的。带有 600,000 次迭代的 PBKDF2 设计为慢以抵抗暴力攻击。如果登录太慢，检查服务器是否有足够的 CPU 资源，而不是迭代次数。

"SecurityContext 在我的 handler 中为 null"

SecurityContext 由中间件创建。确保中间件注册为 RouteContributor，处理程序用 SecuredHandler 包装。
