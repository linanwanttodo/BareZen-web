内核很小，接缝是真的。

BareZen 是给这样的人用的 Java Web 框架：你要把路由、会话和持久化放进一个已经存在的 项目里 —— 用它已有的服务器、它的容器、它的数据库。

JDK 17+ 插件化 零强制依赖 SPI 驱动 
Router routes = Router.builder()
  .route(GET, "/health", (req, params) -> ok())
  .route(GET, "/users/{id}", (req, params) -> user(params.get("id")))
  .build();

var server = new JdkHttpServerAdapter(loopback(0), routes);
server.start();

它适合什么情况

你已经有的BareZen 给你的
一个 Spring Boot / Tomcat / Jetty / Wildfly 部署 BarezenServlet 把 Router 路由进你已经在跑的容器。它不拥有端口也不拥有线程池， 因为那些是你的（ADR-0024、ADR-0049）。
一个不想再引入容器的小服务 JDK 适配器；HTTPS 通过"指定 keystore"来开启，而不是靠一个开关（ADR-0050）。
要自己交付接口的业务团队 插件实现 Plugin 加 RouteContributor，它的路由在任何东西启动之前就已在表里。 在 META-INF/services 里自我声明的 jar，会被 PluginDiscovery 找到 （ADR-0047、ADR-0048）。
一个已有的数据库和它的驱动 Database 接收你的 DataSource，不点名任何驱动；它交给回调的 Transaction，其 commit 与 rollback 是仓储层调不动的 （ADR-0038、ADR-0039）。

功能一览

核心

生命周期管理、配置系统、依赖注入、事件总线和虚拟线程支持。

Web

不可变路由表，包含 Request、Response 和 Handler 契约。

JDK HTTP

内嵌服务器，支持虚拟线程和 TLS/HTTPS。

Servlet

部署到 Tomcat、Jetty 或 Wildfly，无端口冲突。

安全

认证、授权、会话管理和 PBKDF2 密码哈希。

数据

JDBC 查询、事务管理和 Schema 迁移。

插件

SPI 驱动的插件系统，支持路由贡献和自动发现。

TestKit

集成测试工具，包含真实服务器、HTTP 客户端和断言。

接缝，以及它们拒绝什么

插件是一个"能说出自己名字的生命周期参与者"，再加上它所贡献能力的所有者声明的扩展点。这个范围是刻意收窄的： 没有 PluginContext，没有 contribute(ExtensionPoint, T) 注册表，也没有 require(Class) —— 因为那就是一步步走向 ApplicationContext 的那串"小方便"。 插件若需要协作者，就在构造函数里拿，这样读调用点的人能直接看见它需要什么；也因此，需要协作者的插件无法被自动发现， 因为 ServiceLoader 的 provider 只能是无参构造。这个限制是明说的，不是绕过去的。

路由表只回答两个问题 —— 方法加原始路径对应哪个 handler，以及某个路径允许哪些方法 —— 其他什么都不暴露。 没有通配模式，也没有路由枚举，两者都是被名字明确拒绝的（ADR-0019 §19、ADR-0051）：一个接受前缀的匹配器， 会把路由变成一个排序问题。静态文件因此是一个文件一条路由。

这些页面就是普通文件：手写的 HTML、一个样式表、所有地址都是相对路径，原样部署。这正是静态托管方不运行我们的任何 代码就能提供的形状，代价也一并写清楚 —— 这里没有 ETag 条件请求，没有由插件生成的 /openapi.json，一个页面就等于它那个文件写的内容（ADR-0054）。部署前由 scripts/check-site.sh 检查这棵树：它会在磁盘上跟随每一个链接，并要求每个页面都有另一种语言的对应页。
